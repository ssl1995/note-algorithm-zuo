## 一、整体思路：分治
- 左部分排好序、右部分排好序、利用 merge 过程让左右整体有序。
- 这是一个标准的分治递归：把大问题拆成两个一半规模的子问题，子问题排好序后再合并。
- 递归调用的过程（以 arr = {3, 8, 7, 6, 4, 5, 1, 2} 为例）：
```plain
                  mergeSort[0..7]
                 /              \
        mergeSort[0..3]      mergeSort[4..7]
        /          \          /          \
   ms[0..1]    ms[2..3]   ms[4..5]    ms[6..7]
    /   \       /   \      /   \       /   \
  [0]  [1]    [2]  [3]   [4]  [5]    [6]  [7]
先一路拆到单个元素（天然有序），再逐层向上 merge：
  {3,8} {6,7} {4,5} {1,2} -> {3,6,7,8} {1,2,4,5} -> {1,2,3,4,5,6,7,8}
```
## 二、merge 过程：谁小拷贝谁
- 前提：左半 arr[l...m] 和右半 arr[m+1...r] 都已经有序。
- 过程：两个指针分别指向左右两半的开头，谁小就把谁拷贝进辅助数组 help，直到左右两部分所有的数字耗尽，再把 help 中的内容拷贝回原数组。
- 相等时拷贝左边的（arr[a] <= arr[b] 时取 a），保证了归并排序的稳定性。
```java
// l....r 一共有n个数，时间复杂度O(n)
public static void merge(int l, int m, int r) {
    int i = l;
    int a = l;      // 左半指针
    int b = m + 1;  // 右半指针
    while (a <= m && b <= r) {
        help[i++] = arr[a] <= arr[b] ? arr[a++] : arr[b++];
    }
    // 左侧指针、右侧指针，必有一个越界、另一个不越界
    while (a <= m) {
        help[i++] = arr[a++];
    }
    while (b <= r) {
        help[i++] = arr[b++];
    }
    for (i = l; i <= r; i++) {
        arr[i] = help[i];
    }
}
```
- merge 一次的时间复杂度是 O(n)：每个元素恰好被拷贝两次（进 help 一次、回原数组一次）。
## 三、递归实现
- 递归含义：mergeSort1(l, r) 让 arr[l...r] 范围有序；base case 是 l == r（只有一个数，天然有序）。
```java
// 归并排序递归版
// 假设l...r一共n个数
// T(n) = 2 * T(n/2) + O(n)
// a = 2, b = 2, c = 1
// 根据master公式，log(2,2)=1 == c，时间复杂度O(n * logn)
// 空间复杂度O(n)
public static void mergeSort1(int l, int r) {
    if (l == r) {
        return;
    }
    int m = (l + r) / 2;
    mergeSort1(l, m);      // 左半有序
    mergeSort1(m + 1, r);  // 右半有序
    merge(l, m, r);        // 左右整体有序
}
```
- 用 master 公式分析：T(n) = 2 * T(n/2) + O(n)，a=2、b=2、c=1，log(b,a)=1 == c，所以时间复杂度 O(n * logn)。
## 四、非递归实现
- 思路：用步长 step 控制分组大小，step 从 1 开始每次翻倍（step <<= 1），每组内部左右两半 merge；一共发生 O(logn) 轮，每轮整体 O(n)，总复杂度 O(n * logn)。
- 细节：右半可能不足一个 step 甚至不存在，所以 m + 1 >= n 时直接 break，r 用 Math.min 防止越界。
```java
// 归并排序非递归版
// 时间复杂度O(n * logn)
// 空间复杂度O(n)
public static void mergeSort2() {
    // 一共发生O(logn)次
    for (int l, m, r, step = 1; step < n; step <<= 1) {
        // 内部分组merge，时间复杂度O(n)
        l = 0;
        while (l < n) {
            m = l + step - 1;
            if (m + 1 >= n) {
                break;
            }
            r = Math.min(l + (step << 1) - 1, n - 1);
            merge(l, m, r);
            l = r + 1;
        }
    }
}
```
- 以 n = 8 为例，step 的变化：step=1 时两两 merge（共 4 组），step=2 时四四 merge（共 2 组），step=4 时整体 merge（1 组），结束。
## 五、复杂度与"为什么快"
- 时间复杂度 O(n * logn)，需要辅助数组，所以额外空间复杂度 O(n)。
- 归并排序为什么比 O(n^2) 的排序快？因为比较行为没有浪费！
  - 选择、冒泡、插入排序中，每次比较只换来很小的进展，大量比较结果被丢弃。
  - 归并排序中，merge 时每一次比较都确定了一个元素在当前合并段中的相对位置，比较结果通过有序性被后续所有 merge 持续利用，信息没有浪费。
- 稳定性：merge 时相等元素先拷贝左边，相同元素的相对顺序不变，归并排序是稳定排序。
- 注意：有些资料说可以用原地归并排序，把额外空间复杂度变成 O(1)，不要浪费时间去学。因为原地归并排序确实可以省空间，但是会让复杂度变成 O(n^2)，得不偿失。
## 六、笔试中的两种写法
- acm 练习风格（Code01）：自己处理输入输出，用 BufferedReader + StreamTokenizer + PrintWriter 保证读写效率，静态数组 + 静态辅助数组避免频繁申请内存。
- 填函数练习风格（Code02）：只需实现 sortArray(int[] nums)，内部调用 mergeSort1（递归）或 mergeSort2（非递归）均可。
## 七、总结
- 归并排序 = 左右分别排好序 + merge 合并；merge 是谁小拷贝谁，再拷回原数组。
- 递归版按 master 公式 T(n) = 2*T(n/2) + O(n) 得 O(n * logn)；非递归版用 step 翻倍分组，复杂度相同。
- 时间 O(n * logn)、额外空间 O(n)、稳定排序；比 O(n^2) 排序快的本质是"比较行为没有浪费"。
- 利用归并排序的便利性可以解决很多问题（归并分治，如小和问题、逆序对问题）——下节课讲。
