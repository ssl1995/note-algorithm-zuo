## 基于比较的排序 vs 不基于比较的排序
- 基于比较的排序：只需要定义好两个对象之间怎么比较即可，对象的数据特征并不关心，很通用。之前讲的排序（选择、冒泡、插入、归并、快排、堆排）都是基于比较的排序，时间复杂度下限是 O(n * log n)。
- 不基于比较的排序：和比较无关的排序，利用对象的数据特征（比如整数的每一位）来排序，对于对象的数据特征有要求，并不通用。典型代表：计数排序、基数排序、桶排序。
- 一旦比较的对象不再是常规数字（变成字符串、对象等），改写代价的增加是显而易见的，所以不基于比较的排序并不通用。
## 计数排序（铺垫）
- 思想：统计每个数值出现的次数，再按数值大小依次输出。
- 非常简单，但是数值范围比较大了就不行了：要开一个长度为"最大值-最小值+1"的计数数组，范围一大空间就爆炸。
- 一般来讲，计数排序要求：样本是整数，且范围比较窄。
## 基数排序的思想
- 一般来讲，基数排序要求：样本是 10 进制的非负整数（如果不是就需要转化，代码里做了转化，并且代码里可以设置任何进制来进行排序）。
- 核心思想（LSD，从低位到高位）：把每个数按 BASE 进制拆成一位一位的"桶序号"，从最低位开始，对每一位做一轮"稳定的计数排序"，排到最高位后整体就有序了。
- 为什么从低位往高位排最终有序？因为每一轮的分配-收集是稳定的：高位相同时，低位大的数在后面排过序后仍然保持在后面；当处理到更高位时，高位决定主次序，低位的次序被稳定地保留为次次序。
- 举例：对 [203, 101, 31, 2] 做 10 进制基数排序（先补齐成等宽：203、101、031、002）：
  - 第 1 轮按个位入桶：1 号桶 101、31，2 号桶 2，3 号桶 203 → 收集得 [101, 31, 2, 203]
  - 第 2 轮按十位入桶：0 号桶 101、2，3 号桶 31，0 号桶 203 → 收集得 [101, 2, 203, 31]（注意 101、002、203 的十位都是 0，保持上一轮相对次序）
  - 第 3 轮按百位入桶：0 号桶 2、31，1 号桶 101，2 号桶 203 → 收集得 [2, 31, 101, 203]，排序完成
- 基数排序的实现细节，非常优雅的一个实现，关键点：前缀数量分区的技巧、数字提取某一位的技巧。
## 两个关键技巧
- 数字提取某一位的技巧：`(arr[i] / offset) % BASE`，offset 依次取 1、10、100……（BASE 进制下就是 1、BASE、BASE^2……），即可取出个位、十位、百位……上的数字。
- 前缀数量分区的技巧：对当前位做计数得到 cnts[0..BASE-1]（每个桶几个数），再把 cnts 处理成前缀和（cnts[i] = cnts[i] + cnts[i-1]），此时 cnts[d] 表示"当前位 <= d 的数一共有几个"，也就是 d 号桶的数在结果数组中应该占到的右边界。然后从右往左遍历原数组，`help[--cnts[d]] = arr[i]`，把每个数放到它该在的位置。从右往左遍历保证了稳定性（同桶内相对次序不变）。
## 核心代码
```java
// 基数排序核心代码
// arr内要保证没有负数
// bits是arr中最大值在BASE进制下有几位
public static void radixSort(int[] arr, int n, int bits) {
    // 理解的时候可以假设BASE = 10
    for (int offset = 1; bits > 0; offset *= BASE, bits--) {
        Arrays.fill(cnts, 0);
        for (int i = 0; i < n; i++) {
            // 数字提取某一位的技巧
            cnts[(arr[i] / offset) % BASE]++;
        }
        // 处理成前缀次数累加的形式
        for (int i = 1; i < BASE; i++) {
            cnts[i] = cnts[i] + cnts[i - 1];
        }
        for (int i = n - 1; i >= 0; i--) {
            // 前缀数量分区的技巧
            // 数字提取某一位的技巧
            help[--cnts[(arr[i] / offset) % BASE]] = arr[i];
        }
        for (int i = 0; i < n; i++) {
            arr[i] = help[i];
        }
    }
}
```
## 负数的转化处理
- 基数排序要求非负整数，代码里的转化办法：找到数组最小值 min，每个数都减去 min，把 arr 转成非负数组；排完序后每个数再加回 min 还原。
```java
public static int[] sortArray(int[] arr) {
    if (arr.length > 1) {
        // 如果会溢出，那么要改用long类型数组来排序
        int n = arr.length;
        // 找到数组中的最小值
        int min = arr[0];
        for (int i = 1; i < n; i++) {
            min = Math.min(min, arr[i]);
        }
        int max = 0;
        for (int i = 0; i < n; i++) {
            // 数组中的每个数字，减去数组中的最小值，就把arr转成了非负数组
            arr[i] -= min;
            // 记录数组中的最大值
            max = Math.max(max, arr[i]);
        }
        // 根据最大值在BASE进制下的位数，决定基数排序做多少轮
        radixSort(arr, n, bits(max));
        // 数组中所有数都减去了最小值，所以最后不要忘了还原
        for (int i = 0; i < n; i++) {
            arr[i] += min;
        }
    }
    return arr;
}
```
- 细节提醒：如果 arr[i] - min 会溢出（比如最小值是 int 最小值），要改用 long 类型数组来排序；最大值在 BASE 进制下的位数决定排序做多少轮，而不是固定做 10 轮。
## 复杂度分析
- 时间复杂度 O(n)：一共 bits 轮（最大值在 BASE 进制下的位数，可视为常数），每轮 O(n + BASE)，所以总体是 O(n) 级别。
- 额外空间复杂度 O(m)：需要一个和数组等长的辅助数组 help，外加长度为 BASE 的计数数组，需要辅助空间做类似桶的作用，来不停的装入、弹出数字。
- 基数排序是稳定排序（每一轮的"前缀数量分区 + 从右往左收集"保证了稳定性，这也是从低位排到高位能正确工作的前提）。
