## 一、位图原理
- 位图（Bitset / Bitmap）：其实就是用 bit 组成的数组来存放值，用 bit 状态 1、0 代表存在、不存在，取值和存值操作都用位运算。
- 限制：必须为连续范围且不能过大（比如要表示 0~n-1 这些数字是否存在）。
- 好处：极大的节省空间，因为 1 个数字只占用 1 个 bit 的空间。
  - 对比：用 int 数组记录 1 亿个数字的状态需要 1亿 × 4B = 400MB，用位图只需要 1亿 bit ≈ 12.5MB，直接省 32 倍。
  - Java 中一个 int 有 32 个 bit，所以长度为 (n+31)/32 的 int 数组就能装下 n 个数字的状态。
- 典型应用（扩展了解）：
  - 大数据去重/判重：如 40 亿个 QQ 号判断某个号是否出现过（《编程珠玑》经典问题：给 10 亿个不重复的电话号码排序，用的就是位图）。
  - 布隆过滤器（Bloom Filter）：位图 + 多个哈希函数，用少量误判换极致空间，缓存穿透防护常用。
  - 权限/签到系统：一个 bit 表示"是否拥有某权限""某天是否签到"。
## 二、位图的实现（Code01_Bitset）
- 接口设计（只支持 0~n-1 所有数字的增删改查）：
  - Bitset(int n)：初始化位图的大小
  - void add(int num)：把 num 加入到位图
  - void remove(int num)：把 num 从位图中删除
  - void reverse(int num)：如果位图里没有 num，就加入；如果位图里有 num，就删除
  - boolean contains(int num)：查询 num 是否在位图中
- 核心定位公式：num 这个数字的状态存放在第 num/32 个 int 的第 num%32 个 bit 上。
- 小技巧：a/b 结果想向上取整，可以写成 (a+b-1)/b，前提是 a 和 b 都是非负数，所以数组长度是 (n+31)/32。
```java
public static class Bitset {
    public int[] set;
    // n个数字 : 0~n-1
    public Bitset(int n) {
        set = new int[(n + 31) / 32];
    }
    public void add(int num) {
        set[num / 32] |= 1 << (num % 32);
    }
    public void remove(int num) {
        set[num / 32] &= ~(1 << (num % 32));
    }
    public void reverse(int num) {
        set[num / 32] ^= 1 << (num % 32);
    }
    public boolean contains(int num) {
        return ((set[num / 32] >> (num % 32)) & 1) == 1;
    }
}
```
- 四个操作对应四种位运算，本质都是先造出掩码 1 << (num%32)（只有目标位是 1）：
```text
add     : |= 掩码    目标位强制变1（有或没有都变成有）
remove  : &= ~掩码   目标位强制变0（其余位不受影响）
reverse : ^= 掩码    目标位 0/1 互换（异或的天然特性）
contains: >> 后 & 1  把目标位挪到最低位，看它是不是1
```
- 注意：使用时 num 不要超过初始化的大小 n，否则会数组越界。
## 三、对数器验证（找不到测试链接时的标准做法）
- 当你找不到测试链接的时候就用对数器验证，而且对数器验证更稳妥、更能练习 debug 能力。
- 思路：位图和 HashSet 做完全相同的随机操作（add / remove / reverse 各约 1/3 概率），跑 10000 次调用后，逐个数字对比 contains 结果是否一致。
- reverse 操作用 HashSet 模拟：contains 就 remove，否则 add。
```java
public static void main(String[] args) {
    int n = 1000;
    int testTimes = 10000;
    Bitset bitSet = new Bitset(n);        // 实现的位图结构
    HashSet<Integer> hashSet = new HashSet<>(); // 直接用HashSet做对比测试
    for (int i = 0; i < testTimes; i++) {
        double decide = Math.random();
        int number = (int) (Math.random() * n); // 0 ~ n-1 等概率
        if (decide < 0.333) {
            bitSet.add(number);
            hashSet.add(number);
        } else if (decide < 0.666) {
            bitSet.remove(number);
            hashSet.remove(number);
        } else {
            bitSet.reverse(number);
            if (hashSet.contains(number)) {
                hashSet.remove(number);
            } else {
                hashSet.add(number);
            }
        }
    }
    for (int i = 0; i < n; i++) { // 验证阶段：逐一对拍
        if (bitSet.contains(i) != hashSet.contains(i)) {
            System.out.println("出错了!");
        }
    }
}
```
- 实测运行：调用阶段结束、验证阶段结束，无"出错了!"输出，位图实现正确。
## 四、相关测试：LeetCode 2166 设计位集（Code02_DesignBitsetTest）
- 测试链接：https://leetcode.cn/problems/design-bitset/
- 题目要求，Bitset 是一种能以紧凑形式存储位的数据结构：
  - Bitset(int n)：初始化 n 个位，所有位都是 0
  - void fix(int i)：将下标 i 的位上的值更新为 1
  - void unfix(int i)：将下标 i 的位上的值更新为 0
  - void flip()：翻转所有位的值
  - boolean all()：是否所有位都是 1
  - boolean one()：是否至少有一位是 1
  - int count()：返回所有位中 1 的数量
  - String toString()：返回所有位的状态
- 关键难点：如果 flip() 真的去翻转每一个 bit，单次就是 O(n)，会被卡。正确做法是"懒翻转"：
  - 用一个 reverse 布尔标记记录当前位图的 0/1 含义是否被翻转（0 表示存在、还是 1 表示存在），flip() 只翻转标记，O(1) 完成。
  - 同时维护 zeros 和 ones 两个计数器，all()、one()、count() 全部 O(1) 回答，flip() 时交换 zeros 和 ones 即可。
  - fix/unfix 根据 reverse 标记分两套逻辑：reverse=false 时位状态维持原始含义（1 表示存在），reverse=true 时位状态含义反过来了（0 表示存在）。
  - toString() 输出时按 reverse 标记做一次异或修正即可。
```java
class Bitset {
    private int[] set;
    private final int size;
    private int zeros;
    private int ones;
    private boolean reverse;
    public Bitset(int n) {
        set = new int[(n + 31) / 32];
        size = n;
        zeros = n;
        ones = 0;
        reverse = false;
    }
    // 把i这个数字加入到位图
    public void fix(int i) {
        int index = i / 32;
        int bit = i % 32;
        if (!reverse) {
            // 位图所有位的状态，维持原始含义：0不存在、1存在
            if ((set[index] & (1 << bit)) == 0) {
                zeros--;
                ones++;
                set[index] |= (1 << bit);
            }
        } else {
            // 位图所有位的状态，翻转了：0存在、1不存在
            if ((set[index] & (1 << bit)) != 0) {
                zeros--;
                ones++;
                set[index] ^= (1 << bit);
            }
        }
    }
    // 把i这个数字从位图中移除
    public void unfix(int i) {
        int index = i / 32;
        int bit = i % 32;
        if (!reverse) {
            if ((set[index] & (1 << bit)) != 0) {
                ones--;
                zeros++;
                set[index] ^= (1 << bit);
            }
        } else {
            if ((set[index] & (1 << bit)) == 0) {
                ones--;
                zeros++;
                set[index] |= (1 << bit);
            }
        }
    }
    public void flip() {
        reverse = !reverse; // 只翻标记，不动数据，O(1)
        int tmp = zeros;
        zeros = ones;
        ones = tmp;
    }
    public boolean all() {
        return ones == size;
    }
    public boolean one() {
        return ones > 0;
    }
    public int count() {
        return ones;
    }
    public String toString() {
        StringBuilder builder = new StringBuilder();
        for (int i = 0, k = 0, number, status; i < size; k++) {
            number = set[k];
            for (int j = 0; j < 32 && i < size; j++, i++) {
                status = (number >> j) & 1;
                status ^= reverse ? 1 : 0; // 输出时按标记修正
                builder.append(status);
            }
        }
        return builder.toString();
    }
}
```
- 复杂度：fix、unfix、flip、all、one、count 全部 O(1)，只有 toString 是 O(n)。
- 这种"打标记代替真实操作"的懒更新思想非常通用，后续线段树的懒更新、可持久化结构里都会反复用到。
## 五、本节课一句话总结
- 位图 = int 数组当 bit 数组用，num/32 定位到哪个 int、num%32 定位到哪个 bit，add/remove/reverse/contains 对应 |=、&=~、^=、>>&1 四种位运算。
- 向上取整公式 (a+b-1)/b 记住；找不到测试链接就用 HashSet 做对数器验证。
- flip 类整体操作用"懒标记"优化成 O(1)，是 LeetCode 2166 的题眼，也是重要的工程思想。
