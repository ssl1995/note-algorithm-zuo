# 算法讲解040【必备】N皇后问题-重点是位运算的版本
前置知识：递归相关（讲解038）、位运算相关（讲解003、030、031、032、033）
代码位置：src/class040/NQueens.java ｜ 内容：N皇后问题的两种实现（数组路径法 + 位运算法），时间复杂度 O(n!)，位运算版本大幅优化常数时间
## 零、N皇后问题简介
- 题意：在 n×n 的棋盘上摆 n 个皇后，要求任意两个皇后不能在同一行、同一列、同一条对角线上，返回一共有多少种不同的摆法。
- 测试链接：https://leetcode.cn/problems/n-queens-ii/（LeetCode 52. N皇后 II，只要求返回摆法数量）
- 相关题目：https://leetcode.cn/problems/n-queens/（LeetCode 51. N皇后，要求返回所有具体摆法，思路完全一致）
- 因为每行必须放且只能放一个皇后，所以按行依次决策：第 0 行有 n 种选择、第 1 行最多 n-1 种…… 时间复杂度为 O(n!)，无法更优，但好的实现可以大量剪枝、大幅优化常数时间。
- 8 皇后（经典案例）共有 92 种摆法；n 越大解的数量增长极快，对实现的常数效率要求很高。
## 一、用数组表示路径的方法（经典、常数时间慢，不推荐）
- 核心思路：用数组 `path[i]` 记录第 i 行的皇后放在了哪一列；来到第 i 行时，枚举每一列 j，检查是否与 0..i-1 行已摆的皇后冲突，不冲突就摆下并递归到下一行，所有分支的答案累加返回。
- 冲突判断：之前第 k 行皇后在 `path[k]` 列，若 `j == path[k]`（同列）或 `|i - k| == |j - path[k]|`（同对角线，行差等于列差），则冲突。
```java
// i : 当前来到的行
// path : 0...i-1行的皇后，都摆在了哪些列
// 返回 : 0...i-1行已经摆完了，i....n-1行可以去尝试的情况下还能找到几种有效的方法
public static int f1(int i, int[] path, int n) {
    if (i == n) {
        return 1; // 所有行都摆完，找到一种有效方法
    }
    int ans = 0;
    for (int j = 0; j < n; j++) {
        if (check(path, i, j)) { // i行j列能放皇后
            path[i] = j;
            ans += f1(i + 1, path, n);
        }
    }
    return ans;
}
// 当前在i行、j列摆一个皇后，和path[0...i-1]里的皇后会不会冲突
public static boolean check(int[] path, int i, int j) {
    for (int k = 0; k < i; k++) {
        // 同列，或者行差 == 列差（同一条对角线）
        if (j == path[k] || Math.abs(i - k) == Math.abs(j - path[k])) {
            return false;
        }
    }
    return true;
}
```
- 缺点：每放一个皇后都要循环检查之前所有行，单个位置验证代价 O(n)，整体常数时间慢。
## 二、用位运算的方法（巧妙、常数时间快，推荐）
- 核心思路：不再逐行检查，而是用 3 个整数的二进制位，直接表示"当前哪些列不能再放皇后"，一次位运算就能算出所有可放的位置：
  - `col`：0..i-1 行皇后正下方延伸，哪些列不能再放；
  - `left`：0..i-1 行皇后左下方向（右上→左下对角线）延伸，哪些列不能再放；
  - `right`：0..i-1 行皇后右下方向（左上→右下对角线）延伸，哪些列不能再放。
- 每往下一行，列限制不变（`col | place`），左下方向限制整体右移 1 位（`(left | place) >> 1`），右下方向限制整体左移 1 位（`(right | place) << 1`），对角线的"斜向延伸"用移位天然表达。
- 三个关键位运算技巧：
  - `limit = (1 << n) - 1`：低 n 位全为 1，作为位掩码，圈定有效列范围（如 n=5 时 limit = 0b11111）；
  - `candidate = limit & (~(col | left | right))`：总限制取反再与上 limit，位为 1 表示该列可放皇后；
  - `place = candidate & (-candidate)`：lowbit 操作，提取 candidate 中最右侧的 1，逐位枚举每个可放位置，`candidate ^= place` 抹掉已尝试的位。
- 位信息推进示意（以 n=6，candidate = 0b001110 为例，依次提取最右侧的 1 进行尝试）：
```
candidate : 0 0 1 1 1 0   ->  place : 0 0 0 0 1 0（第1列）
candidate : 0 0 1 1 0 0   ->  place : 0 0 0 1 0 0（第2列）
candidate : 0 0 1 0 0 0   ->  place : 0 0 1 0 0 0（第3列）
candidate : 0 0 0 0 0 0   ->  尝试完毕
```
- 当 `col == limit` 时说明 n 列都摆上了皇后，即 n 行全部摆完，找到一种有效方法。
```java
public static int totalNQueens2(int n) {
    if (n < 1) {
        return 0;
    }
    // n = 5 时 limit = 0...011111；n = 7 时 limit = 0...01111111
    int limit = (1 << n) - 1;
    return f2(limit, 0, 0, 0);
}
// limit : 当前是几皇后问题（低n位全1的掩码）
// col   : 之前皇后的列影响（正下方）
// left  : 之前皇后的右上 -> 左下对角线影响
// right : 之前皇后的左上 -> 右下对角线影响
public static int f2(int limit, int col, int left, int right) {
    if (col == limit) {
        return 1; // 所有皇后放完了！
    }
    int ban = col | left | right;      // 总限制
    int candidate = limit & (~ban);    // 1可放皇后，0不能放
    int place = 0;
    int ans = 0;
    while (candidate != 0) {
        place = candidate & (-candidate); // 提取出最右侧的1
        candidate ^= place;               // 抹掉这一位，继续尝试下一个
        ans += f2(limit, col | place, (left | place) >> 1, (right | place) << 1);
    }
    return ans;
}
```
- 优点：一次循环直接枚举所有可放位置，单次尝试只需几次位运算；每次尝试只修改 3 个 int 表示决策，无需数组恢复现场，常数时间远优于数组法。
## 三、两种方法实测对比
- 代码中的 `main` 方法分别用两种方法求解 14 皇后，并单独测试 16 皇后：
```java
int n = 14;
System.out.println("方法1答案 : " + totalNQueens1(n)); // 365596
System.out.println("方法2答案 : " + totalNQueens2(n)); // 365596
// 只有位运算的版本，才能10秒内跑完16皇后问题的求解过程
int ans = totalNQueens2(16); // 14772512
```
- 结论：两种方法答案一致（正确性可互相验证），但位运算版本速度快得多，14 皇后时差距已非常明显；16 皇后（14772512 种摆法）只有位运算版本能在 10 秒内跑完。

## 五、总结
- N皇后问题是回溯+剪枝的经典模型，时间复杂度 O(n!) 无法改变，比拼的是常数时间。
- 数组路径法：思路经典好理解，但每次验证要遍历之前所有行，不推荐。
- 位运算法：用 `col`、`left`、`right` 三个整数的位信息压缩所有限制，`limit & (~ban)` 一步算出所有可放位置，`candidate & (-candidate)` 逐位枚举，左右移位天然表达对角线延伸，是必背的优雅实现。
- 该位运算技巧（状态压缩 + lowbit 枚举）可推广到数独、铺砖等需要在网格上做大量冲突判断的搜索问题。
