## 零、本节课内容概览
- **滑动窗口**：维持**左、右边界都不回退**的一段范围 [l, r]，来求解很多子数组（子串）的相关问题。本质是双指针的一种，两个指针都只朝一个方向走，所以总复杂度是 O(n)。
- **滑动窗口的关键**：找到**范围**和**答案指标**之间的**单调性关系**（类似贪心）——窗口扩大时指标只会朝一个方向变化（变大/变小/变合法/变不合法），才有收缩窗口的意义；没有单调性就不能用滑动窗口。
- **滑动过程**：滑动窗口可以用**简单变量**（累加和、计数器）或者**结构**（词频表、欠债表）来维护窗口内的信息。
- **求解大流程**：求子数组在**每个位置开头**或**每个位置结尾**情况下的答案（用开头还是结尾在于个人习惯，本课多用"以 r 结尾"）。
- 注意：滑动窗口**维持最大值或最小值**的更新结构（单调队列），在【必备】课程【单调队列】视频里讲述，本课不覆盖。
## 一、滑动窗口原理与通用套路
- 通用模板：r 负责右扩进窗口并更新窗口信息；当窗口不再满足条件（或满足条件但还能更优）时，l 右移收缩窗口并弹出信息；每次循环在合适时机更新答案。
```java
for (int l = 0, r = 0; r < n; r++) {
    // 1. nums[r] 进窗口，更新窗口信息
    // 2. while (窗口违规 或 还能更优) { nums[l] 出窗口，l++ }
    // 3. 用当前窗口 [l, r] 更新答案
}
```
- 复杂度保证：l、r 各自最多走 n 步，互不回退，整体 O(n)；窗口信息维护得当则额外空间 O(字符集) 或 O(1)。
- 为什么对：因为存在单调性，当 [l, r] 已经"达标且再缩就不达标"（或"刚好不达标"）时，对当前 r 而言 l 就是最优左边界；r 前进后 l 不可能再回退（回退不会得到更优答案），所以可以不遗漏地枚举所有关键窗口。
- 常见窗口信息维护手段：① 累加和 sum；② `last[c]` 记录字符上次出现位置；③ `cnts[c]` 词频/欠债表 + collect/debt 等汇总计数器。
## 二、题目1：累加和≥target的最短子数组（Code01_MinimumSizeSubarraySum）
- 题意：n 个**正整数**的数组和正整数 target，找到累加和 >= target 的长度最小的子数组，返回其长度，不存在返回 0。测试链接：https://leetcode.cn/problems/minimum-size-subarray-sum/
- 单调性分析：**正整数**是能用滑动窗口的前提——窗口右扩，sum 只增；窗口左缩，sum 只减。所以"sum >= target"这个指标随范围扩大单调变容易。
- 思路：r 右扩累加 sum；只要"把 l 位置的数吐出去后 sum 仍 >= target"，说明 l 位置的数多余，持续吐出；之后若 sum >= target，当前窗口就是以 r 结尾的最短达标窗口，更新答案。
```java
public static int minSubArrayLen(int target, int[] nums) {
    int ans = Integer.MAX_VALUE;
    for (int l = 0, r = 0, sum = 0; r < nums.length; r++) {
        sum += nums[r];
        while (sum - nums[l] >= target) {
            // sum : nums[l....r]
            // 如果l位置的数从窗口出去，还能继续达标，那就出去
            sum -= nums[l++];
        }
        if (sum >= target) {
            ans = Math.min(ans, r - l + 1);
        }
    }
    return ans == Integer.MAX_VALUE ? 0 : ans;
}
```
- 复杂度：时间 O(n)，额外空间 O(1)。
## 三、题目2：无重复字符的最长子串（Code02_LongestSubstringWithoutRepeatingCharacters）
- 题意：给定字符串 s，求不含重复字符的最长子串的长度。测试链接：https://leetcode.cn/problems/longest-substring-without-repeating-characters/
- 思路：`last[c]` 记录每种字符**上次出现的位置**。窗口 [l, r] 要求无重复，当 s[r] 进窗口时，l 只需跳到 `max(l, last[s[r]] + 1)` 即可一步到位跳过冲突位置，l 同样不回退。每次用 `r - l + 1` 更新答案。
```java
public static int lengthOfLongestSubstring(String str) {
    char[] s = str.toCharArray();
    int n = s.length;
    // 每一种字符上次出现的位置，初始都没有出现过
    int[] last = new int[256];
    Arrays.fill(last, -1);
    int ans = 0;
    for (int l = 0, r = 0; r < n; r++) {
        l = Math.max(l, last[s[r]] + 1);
        ans = Math.max(ans, r - l + 1);
        // 更新当前字符上一次出现的位置
        last[s[r]] = r;
    }
    return ans;
}
```
- 亮点：不同于"while 收缩"的写法，这里用 last 数组让 l **直接跳跃**，跳过逐个弹出的过程，是滑动窗口的经典优化。
- 复杂度：时间 O(n)，额外空间 O(字符集)。
## 四、题目3：最小覆盖子串（Code03_MinimumWindowSubstring）
- 题意：给定字符串 s 和 t，返回 s 中**涵盖 t 所有字符**（含重复次数）的最小子串；不存在返回 ""。测试链接：https://leetcode.cn/problems/minimum-window-substring/
- 思路：经典的**欠债表**模型，词频表 + 汇总计数器维护窗口信息：
  1. `cnts[c]` 初始化为 t 中各字符出现次数的**负数**（负债）；`debt = t.length` 表示总债务；
  2. r 右扩，`cnts[s[r]]++`：若加之前 cnts < 0 说明还的是有效债，`debt--`；cnts 为正则表示盈余（多给的）；
  3. `debt == 0` 说明窗口已覆盖 t，此时把左边界盈余的字符全部拿回（`while (cnts[s[l]] > 0) cnts[s[l++]]--`），得到以 r 结尾的最短达标窗口，更新答案。
```java
int[] cnts = new int[256];
for (char cha : t) {
    cnts[cha]--;
}
int len = Integer.MAX_VALUE, start = 0, debt = t.length;
for (int l = 0, r = 0; r < s.length; r++) {
    // 窗口右边界向右，给出字符
    if (cnts[s[r]]++ < 0) {
        debt--;
    }
    if (debt == 0) {
        // 窗口左边界向右，拿回字符
        while (cnts[s[l]] > 0) {
            cnts[s[l++]]--;
        }
        // 以r位置结尾的达标窗口，更新答案
        if (r - l + 1 < len) {
            len = r - l + 1;
            start = l;
        }
    }
}
return len == Integer.MAX_VALUE ? "" : str.substring(start, start + len);
```
- 欠债表思想是滑动窗口处理"覆盖/包含"类问题的通用手法：**负数=负债、正数=盈余、debt=总缺口**，题目5 还会复用这套模型。
- 复杂度：时间 O(n)，额外空间 O(字符集)。
## 五、题目4：加油站（Code04_GasStation）
- 题意：环形路上 n 个加油站，i 站有 gas[i] 升油，从 i 开到 i+1 耗 cost[i] 升，油箱无限、出发时为空。求能绕环行驶一周的出发站编号，不行返回 -1；有解保证唯一。测试链接：https://leetcode.cn/problems/gas-station/
- 思路：把数组**扩充一倍**（下标 0..2n-1，用 `r % n` 取实际余量），问题转化为滑动窗口判定。窗口 [l, r) 表示"从 l 出发能连续到达的站"，sum 为窗口内总余量：
  - 从 l 出发，只要 `sum + gas[r%n] - cost[r%n] >= 0` 就能开到下一站，r 右扩；
  - 当窗口长度达到 n（`r - l + 1 == n` 时即将扩到第 n 个站）说明能转一圈，返回 l；
  - 开不到 r 时，说明 **l 到 r 之间的任何站出发都到不了 r**（因为从 l 出发到这些站时油量非负，从中间出发只会更差），直接令 `l = r + 1, r = l` 继续。
```java
public static int canCompleteCircuit(int[] gas, int[] cost) {
    int n = gas.length;
    // 窗口范围是[l, r)，左闭右开，i位置的余量信息在(r%n)位置
    for (int l = 0, r = 0, sum; l < n; l = r + 1, r = l) {
        sum = 0;
        while (sum + gas[r % n] - cost[r % n] >= 0) {
            // r位置即将右扩，窗口会变大
            if (r - l + 1 == n) { // 此时检查是否已经转了一圈
                return l;
            }
            sum += gas[r % n] - cost[r % n];
            r++;
        }
    }
    return -1;
}
```
- 关键正确性论证：窗口内每一段的累计余量都 >= 0，所以从窗口内任意中间站出发，到达 r 时的油量**不可能比从 l 出发更多**，中间站统统不是答案，l 可以直接跳到 r+1——这就是本题的单调性。
- 复杂度：时间 O(n)（每个位置最多进出窗口一次），额外空间 O(1)。对比暴力 O(n²) 优势巨大。
## 六、题目5：替换子串得到平衡字符串（Code05_ReplaceTheSubstringForBalancedString）
- 题意：只含 'Q','W','E','R' 的字符串 s，长度 n 是 4 的倍数。四种字符各出现 n/4 次即为平衡字符串。通过**替换一个子串**（可换成任意四种字符组合）使 s 平衡，求待替换子串的最小长度；已平衡返回 0。测试链接：https://leetcode.cn/problems/replace-the-substring-for-balanced-string/
- 思路：替换窗口内的字符 ⟺ 要求**窗口外**每种字符的数量都不超过 n/4（超出的部分必须在窗口里被替换掉）。把四种字符映射成 0~3，套用题目3 的**欠债表**模型：
  1. 统计全图词频，超过 n/4 的字符其超出量记为负债 `cnts[i] = n/4 - cnts[i]`（负数），`debt` 为总负债；
  2. debt == 0 说明本来就平衡，返回 0；
  3. 否则滑窗：窗口必须"装下所有超标的字符"，debt 清零后收缩左边界，取最小窗口长度。
```java
int debt = 0;
for (int i = 0; i < 4; i++) {
    if (cnts[i] < n / 4) {
        cnts[i] = 0; // 不超标的字符没有负债
    } else {
        cnts[i] = n / 4 - cnts[i]; // 超出部分记为负债
        debt -= cnts[i];
    }
}
if (debt == 0) {
    return 0;
}
int ans = Integer.MAX_VALUE;
for (int l = 0, r = 0; r < n; r++) {
    if (cnts[s[r]]++ < 0) {
        debt--;
    }
    if (debt == 0) {
        while (cnts[s[l]] > 0) {
            cnts[s[l++]]--;
        }
        ans = Math.min(ans, r - l + 1);
    }
}
return ans;
```
- 亮点：**逆向转化**——不直接思考"窗口里换成什么"，而是转化为"窗口外必须合法"，与最小覆盖子串同构，体现欠债表模型的通用性。
- 复杂度：时间 O(n)，额外空间 O(1)。
## 七、题目6：K个不同整数的子数组（Code06_SubarraysWithKDifferentIntegers）
- 题意：正整数数组 nums 和整数 k，求**恰好包含 k 个不同整数**的子数组数目。测试链接：https://leetcode.cn/problems/subarrays-with-k-different-integers/
- 单调性分析：**恰好 k 个**没有单调性，但**不超过 k 个**有单调性（窗口扩大，种类数只增不减）。经典转化：
  `恰好k个的答案 = 最多k个的答案 - 最多k-1个的答案`
- 思路：写子函数 `numsOfMostKinds(arr, k)` 求"不同整数个数不超过 k 的子数组个数"。窗口 [l, r] 维持种类数 collect <= k 的最大窗口；**以 r 结尾的合法子数组个数 = r - l + 1**（左边界取 l..r 任意位置都合法），逐 r 累加。
```java
public static int subarraysWithKDistinct(int[] arr, int k) {
    return numsOfMostKinds(arr, k) - numsOfMostKinds(arr, k - 1);
}
// arr中有多少子数组，数字种类不超过k
public static int numsOfMostKinds(int[] arr, int k) {
    Arrays.fill(cnts, 1, arr.length + 1, 0);
    int ans = 0;
    for (int l = 0, r = 0, collect = 0; r < arr.length; r++) {
        if (++cnts[arr[r]] == 1) {
            collect++;
        }
        while (collect > k) {
            if (--cnts[arr[l++]] == 0) {
                collect--;
            }
        }
        ans += r - l + 1;
    }
    return ans;
}
```
- 亮点："**恰好 = 最多(k) - 最多(k-1)**"是计数类滑动窗口问题的标志性套路（同类题：替换后的最长重复字符、统计好子数组等），务必掌握。
- 细节：cnts 数组全局复用，每次用 `Arrays.fill(cnts, 1, arr.length + 1, 0)` 只清有效范围，避免 O(MAXN) 清零的常数浪费。
- 复杂度：时间 O(n)，额外空间 O(n)。
## 八、题目7：至少有K个重复字符的最长子串（Code07_LongestSubstringWithAtLeastKRepeating）
- 题意：给定字符串 s 和整数 k，求最长子串，要求子串中**每种字符出现次数都不小于 k**；不存在返回 0。测试链接：https://leetcode.cn/problems/longest-substring-with-at-least-k-repeating-characters/
- 难点：直接对"每种字符都 >= k 次"滑窗没有单调性（右扩可能引入新字符破坏合法性）。**巧解：枚举子串中字符的种类数 require（1~26）**，对每个 require 求"恰好 require 种字符、且每种都 >= k 次"的最长子串，取全局最大。26 次滑窗仍是 O(26·n) = O(n)。
- 思路：对固定的 require，窗口维护两个计数器——`collect`（窗口中种类数）、`satisfy`（窗口中次数 >= k 的种类数）：
  1. r 右扩，`cnts[s[r]] == 1` 时 collect++，`== k` 时 satisfy++；
  2. 种类数超过 require 时收缩左边界，弹出时对称地维护 collect、satisfy；
  3. `satisfy == require` 时窗口内所有种类都达标，更新答案。
```java
for (int require = 1; require <= 26; require++) {
    Arrays.fill(cnts, 0);
    for (int l = 0, r = 0, collect = 0, satisfy = 0; r < n; r++) {
        cnts[s[r]]++;
        if (cnts[s[r]] == 1) {
            collect++;
        }
        if (cnts[s[r]] == k) {
            satisfy++;
        }
        // l....r 种类超了！l位置的字符，窗口中吐出来！
        while (collect > require) {
            if (cnts[s[l]] == 1) {
                collect--;
            }
            if (cnts[s[l]] == k) {
                satisfy--;
            }
            cnts[s[l++]]--;
        }
        // l.....r : 子串以r结尾、种类数不超的最大长度
        if (satisfy == require) {
            ans = Math.max(ans, r - l + 1);
        }
    }
}
```
- 正确性：答案子串一定含 1~26 中的某种 require 数量的字符，枚举全覆盖；固定 require 后"种类数不超过 require"有单调性，滑窗合法。
- 补充：本题官方常见解法是**分治**（用出现次数 < k 的字符做分割点递归），时间最坏 O(n²) 但常数小；左老师这种"枚举种类数 + 26 次滑窗"是严格 O(26·n) 的巧妙做法。
- 复杂度：时间 O(26·n) 即 O(n)，额外空间 O(字符集)。
## 九、总结
- 滑动窗口适用前提：**范围与答案指标之间存在单调性**（类似贪心）；左右边界都只进不退，时间复杂度 O(n)，是解决子数组/子串问题的利器。
- 通用流程：r 进窗口更新信息 → while 条件收缩 l → 更新答案；"以每个位置结尾/开头"二选一固定下来，保证不重不漏。
- 窗口信息维护三件套：简单变量（sum）、位置记录（last[c]）、词频/欠债表（cnts[c] + collect/debt/satisfy 汇总计数器）。
- 欠债表模型（题目3、5）：负数=负债、正数=盈余、debt=总缺口，处理"覆盖/补齐"类问题的通用手法；逆向转化（窗口内替换 ⟺ 窗口外合法）值得体会。
- 计数套路："**恰好 k 个 = 最多 k 个 - 最多 k-1 个**"（题目6），把无单调性的"恰好"转化为有单调性的"不超过"。
- 无单调性时的处理：枚举一个离散维度（题目7 枚举字符种类数 1~26）把问题变得可滑窗；或像加油站（题目4）一样论证"l 到 r 之间都不是答案"实现 l 的跳跃式前进。
- 加油站题的关键论证：窗口内累计余量恒非负 → 中间站出发不会更好 → l 直接跳到 r+1，是滑动窗口"边界跳跃"的典型范例。
- 后续课程：滑动窗口中维护最大/最小值需要**单调队列**，在【必备】课程【单调队列】视频中讲述。
