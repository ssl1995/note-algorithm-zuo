## 一、核心概念
- 1）常数操作：固定时间的操作，执行时间和数据量无关（如数组按下标寻址、加减乘除、位运算等）。
- 2）时间复杂度：一个和数据量有关的操作次数表达式，只要高阶项、不要低阶项、不要常数项。举例：选择、冒泡、插入排序的操作次数都是等差数列求和，形如 a*n² + b*n + c，只保留最高阶项即 O(N²)。
- 3）严格固定流程的算法，一定强调最差情况！比如插入排序，数组完全逆序时才是 O(N²)，分析复杂度按最差情况算。
- 4）算法流程上利用随机行为作为重要部分的，要看平均或者期望的时间复杂度，因为最差的时间复杂度无意义。例如课上"生成相邻值不同的随机数组"：
```java
int n = 10;
int v = 4;
int[] arr1 = new int[n];
arr1[0] = (int) (Math.random() * v);
for (int i = 1; i < n; i++) {
    do {
        arr1[i] = (int) (Math.random() * v);
    } while (arr1[i] == arr1[i - 1]); // 随机重试，次数是期望意义上的常数
}
```
- 5）利用随机行为的算法还有随机快速排序（【必备】课）、跳表（【扩展】课），同样只在乎平均或期望的时间复杂度。
- 6）时间复杂度的内涵：描述算法运行时间和数据量大小的关系。当数据量很大很大时，这种关系相当本质，并且排除了低阶项、常数时间的干扰。
- 7）空间复杂度：强调"额外空间"（不算输入本身占的空间）。常数项时间放弃理论分析、选择用实验来确定，因为不同常数操作的耗时不同。
- 8）什么叫最优解：先满足时间复杂度最优，然后尽量少用空间的解。
## 二、时间复杂度的均摊：动态数组扩容
- 动态数组（Java 中的 ArrayList）底层是固定大小的数组，满了就申请一个更大的新数组（比如 2 倍），把旧数据拷贝过去。
- 单次扩容拷贝是 O(N)，但扩容发生的次数构成等比数列：1 + 2 + 4 + ... + N，总代价约 2N，均摊到每次 add 操作就是 O(1)。
```java
// java中的动态数组是ArrayList
// 各语言中动态数组的初始大小和实际扩容因子可能不同，但均摊都是O(1)
// 课上用2作为扩容因子只是举例
ArrayList<Integer> arr2 = new ArrayList<>();
arr2.add(5); // 0
arr2.add(4); // 1
arr2.add(9); // 2
arr2.set(1, 6); // arr[1]由4改成了6
System.out.println(arr2.get(1));
```
- 并查集、单调队列、单调栈、哈希表等结构，均有"均摊"这个概念，【必备】课都会讲。
## 三、不要用代码结构判断时间复杂度
- 反例1：只有一个 while 循环的冒泡排序，时间复杂度依然是 O(N²)。判断标准是"操作次数和数据量的关系"，不是循环的层数。
```java
// 只用一个循环完成冒泡排序
// 但这是时间复杂度O(N^2)的！
public static void bubbleSort(int[] arr) {
    if (arr == null || arr.length < 2) {
        return;
    }
    int n = arr.length;
    int end = n - 1, i = 0;
    while (end > 0) {
        if (arr[i] > arr[i + 1]) {
            swap(arr, i, i + 1);
        }
        if (i < end - 1) {
            i++;
        } else {
            end--; // 每轮把最大值"冒"到末尾，范围缩小
            i = 0;
        }
    }
}
```
- 反例2：嵌套循环不一定是 O(N²)。下面这段代码内层循环次数是 N/i，总操作次数为 N/1 + N/2 + N/3 + ... + N/N，即 N 倍调和级数，时间复杂度 O(N * logN)。
```java
int N = 200000;
long start = System.currentTimeMillis();
for (int i = 1; i <= N; i++) {
    for (int j = i; j <= N; j += i) {
        // 这两个嵌套for循环，时间复杂度为O(N * logN)
        // 1/1 + 1/2 + 1/3 + ... + 1/n 叫"调和级数"，收敛于O(logN)
        // 所以流程表达式 n/1 + n/2 + ... + n/n 的时间复杂度是O(N * logN)
    }
}
long end = System.currentTimeMillis();
System.out.println("运行时间 : " + (end - start) + " 毫秒");
```
- 对比：把内层改成 j++，操作次数是等差数列 N + (N-1) + ... + 1，就是 O(N²)。实测两者运行时间差距巨大，可用实验验证。
```java
for (int i = 1; i <= N; i++) {
    for (int j = i; j <= N; j++) {
        // 这两个嵌套for循环，时间复杂度为O(N^2)，很明显等差数列
    }
}
```
- 结论：时间复杂度只能在对算法流程充分理解后才能分析出来，而不是简单地看代码结构！甚至有些算法实现用了多层循环嵌套，时间复杂度却是 O(N) 的，【必备】课里会经常见到。
## 四、常见复杂度一览与补充
- 常见复杂度（由小到大）：O(1) < O(logN) < O(N) < O(N*logN) < O(N²) < ... < O(N^k) < O(2^N) < ... < O(k^N) < ... < O(N!)
- 时间复杂度非常重要：可以直接判断某个方法能不能通过一个题目、根据数据量猜解法，【必备】课都会讲。
- 整套课会讲很多算法和数据结构，也会见到很多时间复杂度的表达，持续看课即可。
## 五、附录：等差数列求和公式
- S = n / 2 * (2 * a1 + (n - 1) * d)，其中 S 是等差数列的和，n 是项数，a1 是首项，d 是公差。
- 任何等差数列求和结果都符合：a * n² + b * n + c（a、b、c 为常数），所以等差数列型的操作次数，时间复杂度都是 O(N²)。
