## 零、二分答案法：原理与通用套路
- **适用场景**：直接求最优解很难，但"给定一个候选答案，判断它是否达标"很容易时，用二分答案法把**求最优**转化为**判定可行**。
- 四个步骤：
  1. **估计最终答案可能的范围** [l, r]，可以定得粗略，反正二分不了几次（log 次）；
  2. **分析"问题的答案"和"给定条件"之间的单调性**——答案越大越容易/越难达标，大部分时候只需要用到"自然智慧"；
  3. **建立一个 f 函数**：当答案固定的情况下，判断给定的条件是否达标（或返回与达标相关的指标）；
  4. **在答案范围上不断二分搜索**，每次用 f 函数判断，直到二分结束，找到最合适的答案。
- 核心点：**分析单调性、建立 f 函数**。
- 通用代码模板：
```java
int ans = 0;
for (int l = 下界, r = 上界, m; l <= r;) {
    m = l + ((r - l) >> 1);   // 中点 = 候选答案
    if (f(m) 达标) {           // f：答案固定为 m 时，条件是否满足
        ans = m;               // 记录答案
        r = m - 1;             // 求最小达标值 → 去左侧继续二分
    } else {
        l = m + 1;             // 不达标 → 去右侧
    }
}
return ans;
```
- 注意：这个技巧**常用且重要**，非常的美、精妙，以后的课还会经常见到（如“爱吃香蕉的珂珂”“分割数组”都是大厂高频题）。
- 复杂度套路：f 函数通常是 O(n) 的遍历，二分约 log(答案范围) 次，总复杂度 O(n × log(答案范围))，把"求最优"的枚举/搜索压成 log 级别。
## 一、题目1：爱吃香蕉的珂珂（Code01_KokoEatingBananas）
- 题意：n 堆香蕉，第 i 堆 piles[i] 根。珂珂每小时选一堆吃 k 根（不足 k 根则吃完为止，该小时不再吃）。警卫 h 小时后回来，求能在 h 小时内吃完所有香蕉的**最小速度 k**。测试链接：https://leetcode.cn/problems/koko-eating-bananas/
- 单调性分析：速度 k 越大，吃完所需时间越短 → "能否在 h 小时内吃完"关于 k 单调，可二分。答案范围 [1, max(piles)]。
- f 函数：速度固定为 speed 时，吃完所有香蕉需要几小时。每堆需要 ⌈pile / speed⌉ 小时，累加即可。
- 小技巧：非负数向上取整 `(a + b - 1) / b`（讲解032-位图讲过这种写法）。
```java
// 时间复杂度O(n * log(max))，额外空间复杂度O(1)
public static int minEatingSpeed(int[] piles, int h) {
    // 最小且达标的速度，范围[l,r]
    int l = 1;
    int r = 0;
    for (int pile : piles) {
        r = Math.max(r, pile);
    }
    int ans = 0;
    int m = 0;
    while (l <= r) {
        m = l + ((r - l) >> 1);
        if (f(piles, m) <= h) {
            // 达标！记录答案，去左侧二分
            ans = m;
            r = m - 1;
        } else {
            l = m + 1;
        }
    }
    return ans;
}
// 速度就定成speed，返回吃完所有的香蕉耗费的小时数量
public static long f(int[] piles, int speed) {
    long ans = 0;
    for (int pile : piles) {
        // (a/b)结果向上取整，非负数可以写成(a+b-1)/b
        ans += (pile + speed - 1) / speed;
    }
    return ans;
}
```
## 二、题目2：分割数组的最大值——画匠问题（Code02_SplitArrayLargestSum）
- 题意：非负整数数组 nums 和整数 m，把数组分成 m 个**非空连续**子数组，使得"各子数组和的最大值"最小。测试链接：https://leetcode.cn/problems/split-array-largest-sum/
- 单调性分析：限定的最大和 limit 越大，需要的分段数越少 → "分段数 <= m"关于 limit 单调。答案范围 [0, sum]（精细点可取下界 max(nums)，本题代码用 0 也不影响正确性）。
- f 函数：要求每部分累加和 <= limit，返回**最少需要划分成几部分**——贪心从左往右累加，超过 limit 就开新的一段。若单个数 > limit 则不可能，返回无穷大。
- 图文说明（nums = [7,2,5,10,8]，limit = 15）：
```
[7,2,5] [10] [8] → 3 段（贪心累加，超过15就切）
7+2+5=14 <=15，再加10就超 → 切；10 单独一段；8 单独一段
```
```java
// 时间复杂度O(n * log(sum))，额外空间复杂度O(1)
public static int splitArray(int[] nums, int k) {
    long sum = 0;
    for (int num : nums) {
        sum += num;
    }
    long ans = 0;
    // [0,sum]二分
    for (long l = 0, r = sum, m, need; l <= r;) {
        m = l + ((r - l) >> 1);
        // 必须让数组每一部分的累加和 <= m，请问划分成几个部分才够!
        need = f(nums, m);
        if (need <= k) {
            ans = m;
            r = m - 1;
        } else {
            l = m + 1;
        }
    }
    return (int) ans;
}
// 必须让数组arr每一部分的累加和 <= limit，返回需要的部分数量
public static int f(int[] arr, long limit) {
    int parts = 1;
    int sum = 0;
    for (int num : arr) {
        if (num > limit) {
            return Integer.MAX_VALUE;
        }
        if (sum + num > limit) {
            parts++;
            sum = num;
        } else {
            sum += num;
        }
    }
    return parts;
}
```
- 补充：本题还有个经典的**动态规划**解法（O(n²·m)），在动态规划章节会讲；二分答案法 O(n·log(sum)) 是更优解，也是"画匠问题"的标准套路。
## 三、题目3：机器人跳跃问题（Code03_RobotPassThroughBuilding）
- 题意：N+1 座建筑从 0 到 N 排列，0 号高度为 0。机器人在第 k 个建筑、能量为 E，跳到 k+1 后：若 H(k+1) > E 则失去 H(k+1)-E 能量，否则获得 E-H(k+1) 能量。全程能量不能为负，求能保证通关的**最小初始能量**。测试链接：https://www.nowcoder.com/practice/7037a3d57bbd4336856b8e16a9cafd71
- 单调性分析：初始能量越大越容易通关 → 单调，可二分。答案范围 [0, max(H)]。
- f 函数：初始能量固定为 energy，模拟跳完全程，看能量是否变负。
- **关键陷阱（很阴）**：能量递推 `E' = 2E - H(k+1)`，当 E 很大时能量增长非常恐怖，**会溢出 long**！所以一定要加 `energy >= max`（建筑最大高度）的判断——一旦能量超过最大高度，后面必然通关，**提前返回 true**，既防溢出又提速。
```java
// [l,r]通关所需最小能量的范围，不停二分；max是所有建筑的最大高度
// 时间复杂度O(n * log(max))，额外空间复杂度O(1)
public static int compute(int l, int r, int max) {
    int m, ans = -1;
    while (l <= r) {
        m = l + ((r - l) >> 1);
        if (f(m, max)) {
            ans = m;
            r = m - 1;
        } else {
            l = m + 1;
        }
    }
    return ans;
}
// 初始能量为energy，max是建筑的最大高度，返回能不能通关
public static boolean f(int energy, int max) {
    // 注意！如果给的能量值很大，后续能量增长将非常恐怖，完全可能超出long的范围
    // 所以遍历时一定要加入energy >= max的判断
    // 一旦能量超过高度最大值，后面肯定通关了，可以提前返回。这里很阴
    for (int i = 1; i <= n; i++) {
        if (energy <= arr[i]) {
            energy -= arr[i] - energy;
        } else {
            energy += energy - arr[i];
        }
        if (energy >= max) {
            return true;
        }
        if (energy < 0) {
            return false;
        }
    }
    return true;
}
```
- 补充：本题是牛客网输入输出格式，代码中使用了 `BufferedReader + StreamTokenizer + PrintWriter` 的高效输入输出写法（参考讲解019），提交时类名改成 `Main`。
## 四、题目4：找出第K小的数对距离（Code04_FindKthSmallestPairDistance）
- 题意：数对距离 = 两数绝对差。给定数组 nums 和 k，返回所有数对距离中**第 k 小**的距离。测试链接：https://leetcode.cn/problems/find-k-th-smallest-pair-distance/
- 单调性分析："距离 <= m 的数对数量"随 m 增大单调不减 → 找到最小的 m 使数量 >= k 即为答案。答案范围 [0, max-min]。
- 解法组合：**排序 + 二分答案 + 滑动窗口（双指针）**。先排序使差值有单调性；f 函数统计"差值 <= limit 的数对个数"，用滑动窗口 O(n) 完成：对每个 l，r 右扩到不能再扩，`arr[l..r]` 与 l 配成的合法数对有 r-l 对。
- 图文说明（f 函数内，数组已排序）：
```
l ... r | r+1     →  arr[r+1]-arr[l] > limit 时停
arr[l..r] 范围内的数与 arr[l] 的差值都 <= limit
贡献数对: (l,l+1) (l,l+2) ... (l,r)  共 r-l 对
```
```java
// 时间复杂度O(n*log(n) + log(max-min) * n)，额外空间复杂度O(1)
public static int smallestDistancePair(int[] nums, int k) {
    int n = nums.length;
    Arrays.sort(nums);
    int ans = 0;
    // [0, 最大-最小]，不停二分
    for (int l = 0, r = nums[n - 1] - nums[0], m, cnt; l <= r;) {
        m = l + ((r - l) >> 1);
        // arr中任意两数的差值 <= m 的数字配对，有几对？
        cnt = f(nums, m);
        if (cnt >= k) {
            ans = m;
            r = m - 1;
        } else {
            l = m + 1;
        }
    }
    return ans;
}
// arr中任意两数的差值 <= limit，这样的数字配对有几对？O(n)滑动窗口
public static int f(int[] arr, int limit) {
    int ans = 0;
    for (int l = 0, r = 0; l < arr.length; l++) {
        // l......r r+1
        while (r + 1 < arr.length && arr[r + 1] - arr[l] <= limit) {
            r++;
        }
        ans += r - l;
    }
    return ans;
}
```
- 补充：这是"**第 k 小**"类问题的通用套路——二分"第 k 小的值"，用 f 函数统计"<= 该值的元素个数"，与"有序矩阵中第 k 小的元素"等题一脉相承。
## 五、题目5：同时运行N台电脑的最长时间（Code05_MaximumRunningTimeOfNComputers）
- 题意：n 台电脑，batteries[i] 是第 i 块电池能供一台电脑运行的分钟数。任意整数时刻可以给电脑换电池（不限次数、不耗时、电池不可充电），求 n 台电脑**同时**运行的最长分钟数。测试链接：https://leetcode.cn/problems/maximum-running-time-of-n-computers/
- PPT 点评：开始玩概念了——"**碎片拼接**"！很妙！难想！
- **核心概念（碎片拼接）**：一块电量 > time 的电池，对"运行 time 分钟"这个目标而言，**有效部分只有 time**（一台电脑不能同时用两块电池，超出的电量在这段时间内用不上，只能专供一台电脑）；电量 <= time 的电池是"碎片"，可以任意时刻换着拼接使用。所以判定 time 是否可行：电量 > time 的电池各自认领一台电脑（num--），其余碎片电量总和 sum 若 >= 剩余电脑数 × time，则可行。
- 解法一（单纯二分答案）：范围 [0, sum]，f 用上面的碎片拼接判定。时间 O(n·log(sum))。
```java
// 让num台电脑共同运行time分钟，能不能做到
public static boolean f1(int[] arr, int num, long time) {
    // 碎片电量总和
    long sum = 0;
    for (int x : arr) {
        if (x > time) {
            num--;
        } else {
            // x <= time，是碎片电池
            sum += x;
        }
        if (sum >= (long) num * time) {
            // 碎片电量 >= 台数 * 要求
            return true;
        }
    }
    return false;
}
```
- 解法二（二分答案 + 增加贪心分析，更优）：若 sum > max × num，说明答案一定 >= max，此时**所有电池都是碎片**，直接返回 sum / num 即可；否则答案 < max，二分范围从 [0, sum] 缩到 **[0, max]**，二分次数变少。时间 O(n·log(max))。
```java
// 就是增加了这里的逻辑
if (sum > (long) max * num) {
    // 所有电池都是"碎片拼接"的概念，答案就是 sum / num
    return sum / num;
}
// 最终供电时间一定 < max，在[0, max]上二分，范围更精细
```
## 六、题目6：计算等位时间（Code06_WaitingTime / Code06_WaitingTime2）
- 题意：数组 arr 长度 n 表示 n 个服务员各自服务一个客人的时间，m 个人在等位，你是刚来的第 m+1 个，每个客人遵循"有空位就上"的原则，问你需要等多久。假设 m 远远大于 n（n <= 10^3，m <= 10^9），最优解怎么做？**谷歌面试题，连考了 2 个月**。
- 解法一（堆模拟，验证用）：小根堆存 [醒来时间， 服务时长]，逐个客人弹出最早醒来的服务员再压回。时间 O(m·log n)，m 很大时超时。
- 解法二（二分答案，最优解）：单调性——服务员工作时间 time 越长，能接待的客人越多 → 单调。f 函数：每个服务员工作 time，可接待 `(time / arr[i]) + 1` 位客人（**结束的、开始的客人都算**，所以 +1）。二分找最小的 time 使接待数 >= w+1（你是第 w+1 个）。答案上界 min(arr) × w。时间 O(n·log(min×w))。
```java
// 时间复杂度O(n * log(min * w))，额外空间复杂度O(1)
public static int waitingTime2(int[] arr, int w) {
    int min = Integer.MAX_VALUE;
    for (int x : arr) {
        min = Math.min(min, x);
    }
    int ans = 0;
    for (int l = 0, r = min * w, m; l <= r;) {
        m = l + ((r - l) >> 1);
        // 每个服务员都工作m时间，能给几个客人提供服务
        if (f(arr, m) >= w + 1) {
            ans = m;
            r = m - 1;
        } else {
            l = m + 1;
        }
    }
    return ans;
}
// 每个服务员工作time，可接待几位客人（结束的、开始的客人都算）
public static int f(int[] arr, int time) {
    int ans = 0;
    for (int num : arr) {
        ans += (time / num) + 1;
    }
    return ans;
}
```
- **在线测试版本（Code06_WaitingTime2）**：LeetCode 2187 完成旅途的最少时间（https://leetcode.cn/problems/minimum-time-to-complete-trips/），与题目6几乎一个意思，仅两处关键差异：① 题意是完成 w 趟旅行而非"你是第 w+1 个"，判定条件为 `f(arr, m) >= w`；② f 函数只统计 time 内**完成**的旅行数，`ans += time / num`，**不需要 +1**。另外变量要改成 long。
## 七、题目7：刀砍毒杀怪兽问题（Code07_CutOrPoison）
- 题意：怪兽初始血量 hp，n 个回合，第 i 回合可二选一：刀砍——本回合直接损失 cuts[i] 血，无后续；毒杀——本回合不掉血，之后每回合损失 poisons[i] 血，**所有毒杀效果叠加**。n 回合内没杀死则无法再有新行动，但中毒效果会继续扣血直到怪兽死掉。求怪兽至少多少回合死掉。数据范围：n <= 10^5，hp/cuts/poisons <= 10^9。真实大厂笔试题。
- 单调性分析：给定的回合限制 limit 越大，怪兽越容易死 → 单调，二分回合数，范围 [1, hp+1]（超过 hp+1 回合无意义，砍 1 滴血也要不了更多回合）。
- **f 函数的精彩分析**：限定 limit 回合内杀死怪兽。对于第 i 回合（从 0 开始，j = i+1 表示第几个回合）的决策，刀砍贡献 cuts[i] 即时伤害；毒杀则还能生效 (limit - j) 个后续回合，贡献 (limit - j) × poisons[i] 伤害。**每个回合独立取两者的较大值**，累加即该 limit 下的最大总伤害——因为毒杀效果叠加互不影响，各回合决策互不干扰，贪心取 max 即可。总伤害 >= hp 则达标。
```java
// 时间复杂度O(n * log(hp))，额外空间复杂度O(1)
public static int fast2(int[] cuts, int[] poisons, int hp) {
    int ans = Integer.MAX_VALUE;
    for (int l = 1, r = hp + 1, m; l <= r;) {
        // m中点，一定要让怪兽在m回合内死掉，更多回合无意义
        m = l + ((r - l) >> 1);
        if (f(cuts, poisons, hp, m)) {
            ans = m;
            r = m - 1;
        } else {
            l = m + 1;
        }
    }
    return ans;
}
// limit：回合的限制；返回怪兽能不能在limit回合内死掉
public static boolean f(int[] cuts, int[] posions, long hp, int limit) {
    int n = Math.min(cuts.length, limit);
    for (int i = 0, j = 1; i < n; i++, j++) {
        // 第i回合：刀砍即时伤害cuts[i]  vs  毒杀后续(limit-j)回合的叠加伤害
        hp -= Math.max((long) cuts[i], (long) (limit - j) * (long) posions[i]);
        if (hp <= 0) {
            return true;
        }
    }
    return false;
}
```
- 验证：本题无在线测试链接，课程用**对数器**验证——`fast1` 是动态规划暴力（三维 dp，仅用于验证，数据量大超时，学完动态规划章节后可回看），`fast2` 是二分答案最优解，随机小数据对拍 10000 组。
- 注意溢出：`(limit - j) * poisons[i]` 最大 10^5 × 10^9 = 10^14，必须强转 long。
## 八、总结
- **二分答案法四步走**：定答案范围（粗略无妨）→ 分析答案与条件的单调性 → 建 f 函数（答案固定时判断是否达标）→ 在范围上二分。核心点是**分析单调性、建立 f 函数**。
- 本质思想：把"求最优解"转化为"判定可行性"，当**判定比求解容易**且答案有单调性时，二分答案法往往就是最优解，复杂度通常是 O(n × log(答案范围))。
- 常见单调性模型：速度/能力越大越省时（珂珂）、上限越大分段越少（画匠）、初始能量越大越容易通关（机器人）、阈值越大计数越多（第 K 小距离、等位时间）、时间越长越容易杀死（刀砍毒杀）。
- 技巧积累：
  - 向上取整 `(a + b - 1) / b`（题目1）；
  - 答案范围精细化：能缩则缩，如题目5用 sum > max×num 的贪心分析把二分范围从 [0,sum] 缩到 [0,max]；
  - f 函数内防溢出：机器人题 `energy >= max` 提前返回（否则 long 溢出，很阴）、刀砍毒杀题强转 long；
  - "碎片拼接"概念（题目5）：超出目标的电池有效量按目标值截断，其余任意拼接；
  - 二分答案 + 排序 + 滑动窗口的组合拳（题目4）；
  - f 函数中每回合独立取 max 的贪心判定（题目7），依赖"毒杀叠加、决策互不干扰"的结构分析。
- 无在线测试链接的题（题目6、7）：用**对数器**（暴力/堆模拟/动态规划）与二分答案解对拍验证，这正是前置知识讲解005/042 的实战应用。
