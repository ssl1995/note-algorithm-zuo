## 零、本节课内容概览
- 一个基本事实：C/C++ 运行 1s、Java/Python/Go 等其他语言运行 1s~2s，对应的常数指令操作量是 **10^7 ~ 10^8**，不管什么测试平台、不管什么 CPU，都是这个数量级。因此可以根据这个基本事实，猜测自己设计的算法能否在规定时间内通过。
- 运用"根据数据量猜解法"技巧的必要条件：
  1. 题目要给定各个入参的范围最大值（正式笔试、比赛的题目一定会给，面试中要和面试官确认）；
  2. 对于自己设计的算法，时间复杂度要有准确的估计。
- 这个技巧太重要了：既可以提前获知自己的方法能不能通过，也可以对题目的分析起到引导作用（看到数据量就能反推出题人期望的复杂度，从而锁定算法方向）。
## 一、问题规模和可用算法对照表
- 数据量 n 与各复杂度算法能否通过的对照表：
| 数据量 | logn | n | n*logn | n*√n | n^2 | 2^n | n! |
| --- | --- | --- | --- | --- | --- | --- | --- |
| n <= 11 | Yes | Yes | Yes | Yes | Yes | Yes | Yes |
| n <= 25 | Yes | Yes | Yes | Yes | Yes | Yes | No |
| n <= 5000 | Yes | Yes | Yes | Yes | Yes | No | No |
| n <= 10^5 | Yes | Yes | Yes | Yes | No | No | No |
| n <= 10^6 | Yes | Yes | Yes | No | No | No | No |
| n <= 10^7 | Yes | Yes | No | No | No | No | No |
| n >= 10^8 | Yes | No | No | No | No | No | No |
- 表中每个复杂度，之前的课上都讲过对应的过程。其中 `n*√n` 常出现在"莫队算法"能解决的题目里，后续【挺难】课程会系统讲述。
- 这张表其实作用有限：时间复杂度的估计很多时候并不由一个入参决定，可能是多个入参共同决定，比如 O(n*m)、O(n+m) 等。
- **最关键的就是记住常数指令操作量是 10^7 ~ 10^8**，然后看自己方法的复杂度落在哪里，就可以估计能否通过。
## 二、题目1：最优的技能释放顺序（n 只有 10，直接全排列）
- 题意：打怪游戏，有 n 个技能，每个技能有伤害 x[i]；若怪物血量小于等于 y[i]，则该技能造成双倍伤害。每个技能最多释放一次，怪物有 m 点血量，问最少用几个技能能消灭它（血量 <= 0）。
- 数据量：1 <= n <= 10；1 <= m、x[i]、y[i] <= 10^6。
- 测试链接：https://www.nowcoder.com/practice/d88ef50f8dab4850be8cd4b95514bbbd（提交时主类名改成 Main，可直接通过）。
- 根据数据量猜解法：n <= 10，全排列复杂度 n! = 10! ≈ 3.6 × 10^6，远小于 10^7~10^8 的常数指令上限，所以**暴力枚举所有技能释放顺序**完全可以通过。m 和 x[i] 虽然到 10^6，但它们不是枚举维度，不影响复杂度估计。
- 解法：用"交换式全排列"递归（参考讲解038），`f(n, i, r)` 表示当前来到 i 号位置、怪兽剩余血量为 r，返回杀死怪兽最少用几个技能：
```java
// n : 一共几个技能；i : 当前来到了第几号技能；r : 怪兽目前的剩余血量
public static int f(int n, int i, int r) {
    if (r <= 0) { // 之前的决策已经让怪兽挂了，返回使用了几个技能
        return i;
    }
    if (i == n) { // 技能用完怪兽还没死，无效
        return Integer.MAX_VALUE;
    }
    int ans = Integer.MAX_VALUE;
    for (int j = i; j < n; j++) {
        swap(i, j); // j号技能来到i位置，试一下这个顺序
        // 剩余血量 > blood[i] 触发双倍伤害，否则单倍
        ans = Math.min(ans, f(n, i + 1, r - (r > blood[i] ? kill[i] : kill[i] * 2)));
        swap(i, j); // 恢复现场
    }
    return ans;
}
```
- 要点：递归到 `r <= 0` 时返回 `i`（恰好是已使用技能数）；每个位置枚举后面所有技能交换过来试一遍，就是标准的全排列暴力，10! 的规模轻松通过。
## 三、题目2：超级回文数的数目（大数据量 → 种子生成 + 打表）
- 题意：如果一个正整数自身是回文数，而且它也是一个回文数的平方，则称它为超级回文数。给定字符串形式的 L 和 R，返回 [L, R] 中超级回文数的数目。
- 数据量：1 <= len(L) <= 18，1 <= len(R) <= 18，即 L、R 表示 [1, 10^18) 范围的整数。
- 测试链接：https://leetcode.cn/problems/super-palindromes/（LeetCode 906. 超级回文数）。
- 根据数据量猜解法（枚举量的三次缩水）：
  - x 范围 [1, 10^18)，直接枚举 x 是 10^18 级别，不可能；
  - x 是"回文数的平方"，枚举根号 num = √x，范围降到 10^9 级别，还是太大；
  - num 本身也是回文数，回文数由它的一半（种子 seed）唯一决定，10^9 以内的回文数只需要枚举 10^5 级别的种子（123 → 12321 / 123321），枚举量再降到约 2 × 10^5，稳稳通过！
- 方法1：种子生成回文数 + 验证。核心代码：
```java
public static int superpalindromesInRange1(String left, String right) {
    long l = Long.valueOf(left);
    long r = Long.valueOf(right);
    long limit = (long) Math.sqrt((double) r); // 根号x的上界
    long seed = 1; // 枚举量很小：10^18 -> 10^9 -> 10^5
    long num = 0;
    int ans = 0;
    do {
        num = evenEnlarge(seed); // seed生成偶数长度回文：123 -> 123321
        if (check(num * num, l, r)) {
            ans++;
        }
        num = oddEnlarge(seed); // seed生成奇数长度回文：123 -> 12321
        if (check(num * num, l, r)) {
            ans++;
        }
        seed++;
    } while (num < limit);
    return ans;
}
```
- 种子扩充成回文数的两个工具函数：
```java
// 根据种子扩充到偶数长度的回文数字：123 -> 123321
public static long evenEnlarge(long seed) {
    long ans = seed;
    while (seed != 0) {
        ans = ans * 10 + seed % 10;
        seed /= 10;
    }
    return ans;
}
// 根据种子扩充到奇数长度的回文数字：123 -> 12321（种子最高位不重复）
public static long oddEnlarge(long seed) {
    long ans = seed;
    seed /= 10;
    while (seed != 0) {
        ans = ans * 10 + seed % 10;
        seed /= 10;
    }
    return ans;
}
```
- 方法2：打表法（必然最优解，连二分都懒得用）。先用 `collect()` 方法（同方法1的逻辑，把范围开到 long 上限）离线跑出所有超级回文数，**一共只有 86 个**（实测验证），直接把结果硬编码进 `record` 数组；查询时只需找到 >= l 的第一个位置 i 和 <= r 的最后一个位置 j，答案就是 `j - i + 1`：
```java
public static int superpalindromesInRange2(String left, String right) {
    long l = Long.parseLong(left);
    long r = Long.parseLong(right);
    int i = 0;
    for (; i < record.length; i++) {
        if (record[i] >= l) { // 第一个 >= l 的位置
            break;
        }
    }
    int j = record.length - 1;
    for (; j >= 0; j--) {
        if (record[j] <= r) { // 最后一个 <= r 的位置
            break;
        }
    }
    return j - i + 1;
}
// record 数组（打表结果，部分展示）：
// 1, 4, 9, 121, 484, 10201, 12321, 14641, 40804, 44944, 1002001, ...
// 4000000008000000004 —— long 范围内总共只有 86 个超级回文数
```
- 启示：当答案在整个数据范围内**总数非常少**时，离线打表硬编码是最快的解法；本题的"种子生成"技巧保证了打表过程本身也很快。课程同时提供了方法1和方法2的 C++ 版本（src/class043 中以注释形式给出），提交均可直接通过。
## 四、题目3：判断一个数字是不是回文数（题目2拆出的小题）
- 测试链接：https://leetcode.cn/problems/palindrome-number/（LeetCode 9. 回文数）。
- 思路：不转字符串，直接数值上首尾对比。先求出最高位的 offset（如 52725 对应 offset = 10000），每次比较 `num / offset`（首）与 `num % 10`（尾），然后掐头去尾 `num = (num % offset) / 10`，offset 除以 100：
```java
public static boolean isPalindrome(int num) {
    if (num < 0) {
        return false;
    }
    int offset = 1;
    // 注意这么写（num/offset>=10）是为了防止 offset *= 10 溢出
    while (num / offset >= 10) {
        offset *= 10;
    }
    // 首尾判断
    while (num != 0) {
        if (num / offset != num % 10) {
            return false;
        }
        num = (num % offset) / 10;
        offset /= 100;
    }
    return true;
}
```
- 注意点：求 offset 时用 `num / offset >= 10` 作为循环条件，而不是 `offset <= num / 10` 之后再乘，是为了防止 offset 本身乘 10 时溢出（long 版本同理）。
## 五、总结
- 天字第一号重要技巧：**常数指令操作量 10^7 ~ 10^8**，看到入参范围就先估计复杂度量级，判断算法能不能过、并反推出题方向。
- 对照表速记：n! 只能到 n ≈ 11；2^n 只能到 n ≈ 25；n^2 只能到 n ≈ 5000；n*logn 能到 10^6 级别；n 能到 10^7；n >= 10^8 基本只能 logn。
- 多入参时复杂度由多个入参共同决定（如 O(n*m)），不要死套表格，算出总操作量再和 10^7~10^8 比较。
- 题目1：n <= 10 → 全排列 10! ≈ 3.6×10^6，暴力枚举技能顺序就是正解。
- 题目2：枚举量三连降 10^18 → 10^9（开根号）→ 10^5（回文由种子决定），种子生成回文法轻松通过；更进一步，答案总共只有 86 个，直接打表硬编码就是最优解。
- 猜解法技巧与上一节课（讲解042 对数器打表找规律）相辅相成：一个帮你锁定复杂度方向，一个帮你在大数据范围下用规律一击必杀。
