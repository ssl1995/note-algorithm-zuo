## 零、本节课内容概览
- 前缀树又叫字典树，英文名 trie：每个样本都从头节点开始，根据前缀字符或者前缀数字建出来的一棵大树，就是前缀树。建树规则一句话：**没有路就新建节点；已经有路了，就复用节点**。
- 前缀树的使用场景：需要根据**前缀信息**来查询的场景。
- 前缀树的优点：根据前缀信息选择树上的分支，可以节省大量的时间。
- 前缀树的缺点：比较浪费空间，空间消耗和**总字符数量**、**字符的种类**有关。
- 前缀树的定制：pass、end 等信息（本节核心）。
- 本节课讲前缀树的原理和代码；下节课（讲解045）是前缀树相关题目讲解，展示前缀树在解题时的常见用法。
- 要实现的前缀树 Trie 类（LeetCode 208 加强版）：
  1. `Trie()` 初始化前缀树对象；
  2. `void insert(String word)` 将字符串 word 插入前缀树中；
  3. `int search(String word)` 返回前缀树中字符串 word 的实例个数；
  4. `int prefixNumber(String prefix)` 返回前缀树中以 prefix 为前缀的字符串个数；
  5. `void delete(String word)` 从前缀树中移除字符串 word。
## 一、前缀树原理：pass 和 end 两个关键信息
- 以前缀树里依次加入 "abc"、"abd"、"ab"、"bcd"、"bce"、"efg" 为例，每个字符串从头节点（空串，通常记为 root）出发，逐字符向下建路：
  - 插入 "abc"：root 下没有 'a' 这条路 → 新建节点 a；a 下没有 'b' → 新建 b；b 下没有 'c' → 新建 c；
  - 插入 "abd"：root → a → b 的路已经存在 → **复用**，只在 b 下新建 d；
  - 插入 "bcd"、"bce"：root 下新建 b（注意这个 b 是 root 的另一个孩子，和 a 下的 b 不是同一个节点），b 下 c 复用，c 下分别建 d、e。
- 树的每条"路"（边）对应一个字符，从 root 到任意节点经过的字符拼起来就是一个**前缀**；所有以某前缀开头的字符串，都会经过同一个节点——这正是前缀树能高效做前缀统计的原因。
- 节点上定制两个计数信息，一切查询都靠它们：
  - **pass**：有多少个字符串在加入时**路过**了这个节点（即有多少个字符串以"root 到该节点的路径"为前缀）；
  - **end**：有多少个字符串**恰好结尾**在这个节点（即该路径对应的完整字符串被插入了几次）。
- 有了 pass 和 end：
  - `search(word)`：沿着 word 的字符走到底，返回最后节点的 `end`（中途没路返回 0）；
  - `prefixNumber(pre)`：沿着 pre 走到底，返回最后节点的 `pass`（中途没路返回 0）。
- 图示（插入 "abc"、"abd"、"ab" 后，节点标注 `(pass, end)`）：
```
root(3, 0)
 └── a(3, 0)
      └── b(3, 1)          ← "ab" 在这里结尾，end=1
           ├── c(1, 1)     ← "abc" 在这里结尾
           └── d(1, 1)     ← "abd" 在这里结尾
```
## 二、前缀树的两种实现方式
- 1）类描述的实现方式（动态结构）。**不推荐！虽然最常用**（面试、网上题解里最常见）。
  - 路的可能性范围较小（如只有小写字母 26 种），用**固定数组**实现路；
  - 路的可能性范围较大（如任意字符），用**哈希表**实现路。
- 2）静态数组的实现方式。**推荐！不仅笔试，就连比赛也能保证使用。**
  - 一切都是静态数组来实现，提交前准备好够用的空间；
  - 如果路的可能性范围较大，就用每一位的信息建树（下节课前缀树的题目里展示，比如 01 字典树按二进制位建路，每个节点只有 2 条路）。
## 三、类描述的实现方式（Code01_TrieTree.java，不推荐）
- 测试链接：https://leetcode.cn/problems/implement-trie-ii-prefix-tree/ （LeetCode 1804. 实现 Trie II，提交时把类名、构造方法改为 Trie）。
- 节点结构：`pass`、`end`、`nexts`（路）。路用固定数组实现时 `nexts = new TrieNode[26]`，字符 `c` 对应下标 `c - 'a'`。
- **insert**：沿途所有节点（含 root）`pass++`，结尾节点 `end++`：
```java
public void insert(String word) {
    TrieNode node = root;
    node.pass++;
    for (int i = 0, path; i < word.length(); i++) { // 从左往右遍历字符
        path = word.charAt(i) - 'a'; // 由字符，对应成走向哪条路
        if (node.nexts[path] == null) {
            node.nexts[path] = new TrieNode(); // 没有路就新建节点
        }
        node = node.nexts[path]; // 有路就复用节点
        node.pass++;
    }
    node.end++;
}
```
- **erase（删除一次）**：先确认 word 确实插入过（`countWordsEqualTo(word) > 0`），再沿途 `pass--`；关键技巧：**当某个下级节点的 pass 减到 0 时，直接把这条路断开（置 null）并 return**，因为它下面挂的所有节点都不可能再被其他字符串用到了：
```java
public void erase(String word) {
    if (countWordsEqualTo(word) > 0) {
        TrieNode node = root;
        node.pass--;
        for (int i = 0, path; i < word.length(); i++) {
            path = word.charAt(i) - 'a';
            if (--node.nexts[path].pass == 0) {
                node.nexts[path] = null; // 整棵子树都没用了，直接断掉
                return;
            }
            node = node.nexts[path];
        }
        node.end--;
    }
}
```
- **查询**：两个查询都是"沿路走到底，没路返回 0"，区别只在最后返回 `end` 还是 `pass`：
```java
// 查询前缀树里，word单词出现了几次
public int countWordsEqualTo(String word) {
    TrieNode node = root;
    for (int i = 0, path; i < word.length(); i++) {
        path = word.charAt(i) - 'a';
        if (node.nexts[path] == null) {
            return 0;
        }
        node = node.nexts[path];
    }
    return node.end;
}
// 查询前缀树里，有多少单词以pre做前缀
public int countWordsStartingWith(String pre) {
    // ... 同样的沿路走法 ...
    return node.pass;
}
```
- 路用哈希表实现（Trie2）：逻辑一模一样，只是把 `nexts[path]` 换成 `HashMap<Integer, TrieNode>` 的 `containsKey / put / get`，字符不用减 `'a'`，直接用字符本身（`path = word.charAt(i)`）做 key。适合字符范围大（如任意 Unicode 字符）的场景。
## 四、静态数组的实现方式（Code02_TrieTree.java，推荐！）
- 测试链接：https://www.nowcoder.com/practice/7f8a8553ddbf4eaab749ec988726702b （牛客【模板】前缀树，提交时类名改成 Main，可直接通过）。
- 核心思想：**不开任何对象**，用三个静态数组模拟整棵树，用下标（节点编号）代替节点引用：
  - `tree[i][j]`：i 号节点走向字符 j 的那条路，通向哪个节点编号；0 表示没有路（0 号位废弃不用）；
  - `end[i]`：i 号节点的 end 值；`pass[i]`：i 号节点的 pass 值；
  - `cnt`：目前用到几号节点了；**1 号节点固定为 root**；`build()` 只需 `cnt = 1`。
```java
public static int MAXN = 150001;             // 如果将来增加了数据量，就改大这个值
public static int[][] tree = new int[MAXN][26]; // tree[i][j]: i号节点走j号路到达的节点编号
public static int[] end = new int[MAXN];
public static int[] pass = new int[MAXN];
public static int cnt;
public static void build() {
    cnt = 1; // 1号节点是root
}
public static void insert(String word) {
    int cur = 1;
    pass[cur]++;
    for (int i = 0, path; i < word.length(); i++) {
        path = word.charAt(i) - 'a';
        if (tree[cur][path] == 0) {
            tree[cur][path] = ++cnt; // 没有路：申请一个新节点编号
        }
        cur = tree[cur][path];
        pass[cur]++;
    }
    end[cur]++;
}
```
- 查询和类描述版本同构，只是把"引用跳转"换成"编号跳转"：
```java
public static int search(String word) {
    int cur = 1;
    for (int i = 0, path; i < word.length(); i++) {
        path = word.charAt(i) - 'a';
        if (tree[cur][path] == 0) {
            return 0;
        }
        cur = tree[cur][path];
    }
    return end[cur];
}
public static int prefixNumber(String pre) {
    // ... 同样的沿路走法 ...
    return pass[cur];
}
```
- 删除：同样先确认存在再删；`--pass[tree[cur][path]] == 0` 时把路清成 0 并返回。注意老师特别说明：**`pass[cur]--`（root 的 pass）这一行讲课时没加**，本题不会用到 `pass[1]` 的信息，加不加都能过，但正确写法应该加上：
```java
public static void delete(String word) {
    if (search(word) > 0) {
        int cur = 1;
        pass[cur]--; // 讲课时漏掉的一行，正确写法应加上
        for (int i = 0, path; i < word.length(); i++) {
            path = word.charAt(i) - 'a';
            if (--pass[tree[cur][path]] == 0) {
                tree[cur][path] = 0; // 该分支不再被任何字符串使用，断路
                return;
            }
            cur = tree[cur][path];
        }
        end[cur]--;
    }
}
```
- 多组数据之间要清空（只清用过的节点，`1 ~ cnt`），不要每次新建大数组：
```java
public static void clear() {
    for (int i = 1; i <= cnt; i++) {
        Arrays.fill(tree[i], 0);
        end[i] = 0;
        pass[i] = 0;
    }
}
```
- 输入输出处理（讲解019的高效率写法，务必参考）：`BufferedReader + PrintWriter`，边读边处理，最后 `flush`：
```java
BufferedReader in = new BufferedReader(new InputStreamReader(System.in));
PrintWriter out = new PrintWriter(new OutputStreamWriter(System.out));
String line = null;
while ((line = in.readLine()) != null) {
    build();
    m = Integer.valueOf(line);
    for (int i = 1; i <= m; i++) {
        splits = in.readLine().split(" ");
        op = Integer.valueOf(splits[0]);
        if (op == 1) {          // 加入字符串
            insert(splits[1]);
        } else if (op == 2) {   // 删除字符串
            delete(splits[1]);
        } else if (op == 3) {   // 查询字符串是否存在
            out.println(search(splits[1]) > 0 ? "YES" : "NO");
        } else if (op == 4) {   // 查询以某字符串为前缀的字符串数量
            out.println(prefixNumber(splits[1]));
        }
    }
    clear();
}
out.flush();
```
## 五、复杂度分析与两种实现对比
- 设字符串长度为 L，则 insert / search / prefixNumber / delete 的时间复杂度都是 **O(L)**——和树里存了多少字符串**无关**！这是前缀树最大的魅力：查询代价只和"要查的串有多长"有关，和"数据总量"无关。
- 空间复杂度：O(所有字符串的字符总数 × 路的可能性)。比如 n 个总长为 S 的小写字符串，静态数组版最多开 S×26 的二维数组。所以前缀树是典型**空间换时间**的结构，字符种类越多越费空间（26 个小写字母还能接受，所有汉字就爆炸）。
- 两种实现对比：
| 维度 | 类描述（new 对象） | 静态数组（推荐） |
| --- | --- | --- |
| 空间 | 每个节点一个对象，对象头开销大 | 连续数组，紧凑可控 |
| 速度 | 大量 new 触发 GC，常数大 | 纯数组下标访问，常数极小 |
| 空间预估 | 不好控制，容易 MLE | 提前算好 MAXN，一次开够 |
| 适用场景 | 面试口述、LeetCode 单题 | 笔试、比赛，稳定通过 |
- 与哈希表对比：哈希表查"整个字符串是否存在"是 O(L)（算哈希要扫一遍串），和前缀树一样；但哈希表**完全无法**做"以 pre 为前缀的字符串有几个"这类前缀统计，这正是前缀树的不可替代性。
## 六、扩充：前缀树的经典应用与变种
- 典型应用场景：
  - **前缀统计/自动补全**：搜索引擎输入提示、IDE 代码补全、通讯录按前缀检索——本质上就是 `prefixNumber` 加沿途收集；
  - **词频统计**：统计海量字符串中每个串出现次数（end 计数），尤其适合大量公共前缀的数据；
  - **字符串排序**：对前缀树做一次先序遍历，得到的就是字典序排序结果；
  - **工程实践**：Elasticsearch 倒排索引的词项字典（FST，可看作压缩的自动机/前缀树思想）、IP 路由表的最长前缀匹配（按 0/1 位建树的 bit-wise Trie）。
- **01 字典树（01-Trie）——求最大异或值**：把每个整数的二进制表示（从高位到低位共 31 位，高位补 0 对齐）看成 01 字符串建树，每个节点只有 0、1 两条路。查询"集合中哪个数和 x 异或最大"时，从最高位开始**贪心**：能走和 x 当前位**相反**的路就走（该位异或出 1），否则走相同的路。因为高位异或出 1 的收益大于所有低位之和，贪心正确。单次查询 O(31)，经典题：洛谷 P4551 最长异或路径、LeetCode 421. 数组中两个数的最大异或值。查询核心代码：
```java
// tree[i][0..1] 表示 0/1 两条路，从最高位 i=30 往低位查
public static int maxXor(int x) {
    int cur = 1, ans = 0;
    for (int i = 30, path, want; i >= 0; i--) {
        path = (x >> i) & 1;      // x 的第 i 位
        want = path ^ 1;          // 贪心：想走相反的路
        if (tree[cur][want] == 0) {
            want = path;          // 没有相反的路，只能走相同的路
        }
        ans |= (path ^ want) << i; // 这一位能异或出的值
        cur = tree[cur][want];
    }
    return ans;
}
```
- **压缩字典树（Radix Tree / 基数树）**：普通前缀树中大量"只有一个孩子"的节点既浪费空间又增加树高，Radix Tree 把这种单链压缩成一个节点（边上存一串字符而非一个字符），查询时一次比较多个字符。常用于 Linux 内核内存管理、HTTP 路由器、Redis Stream 等。代价是插入/删除时多了"压缩节点的分裂与合并"逻辑。
- **可持久化 01 字典树**：需要查询"区间 [l, r] 内与 x 异或的最大值"时，不能每次重建树，可持久化 01-Trie 让每个前缀版本共享历史节点，类似主席树的思想，是竞赛进阶内容。
- **删除操作的工程简化**：工程上树状结构删除代价大，常用"标记删除"（只减 end/pass，不真正断路），当标记删除的节点比例达到一定阈值（如 10%）时再统一重建清理。
## 七、总结
- 前缀树 = 从头节点开始按前缀字符建出的大树，**没路新建、有路复用**，节点上挂 pass（路过次数）、end（结尾次数）即可支持插入、删除、单词计数、前缀计数四大操作。
- 所有操作复杂度 O(字符串长度)，与数据总量无关；代价是空间，和总字符数、字符种类数有关，典型空间换时间。
- 实现首选**静态数组**（编号代替引用，`tree[i][j]` + `end[]` + `pass[]` + `cnt`），笔试比赛都能稳过；类描述版本（数组路 / 哈希表路）了解即可。
- 删除的关键细节：先查存在再删，沿途 pass--，某节点 pass 减到 0 说明整棵子树都没用了，直接断路返回；root 的 pass 也要记得减。
