## 一、归并分治的原理
- 思考一个问题在大范围上的答案，是否等于：左部分的答案 + 右部分的答案 + 跨越左右产生的答案。
- 计算"跨越左右产生的答案"时，如果加上左、右各自有序这个设定，会不会获得计算的便利性？
- 如果以上两点都成立，那么该问题很可能被归并分治解决（话不说满，因为总有很毒的出题人）。
- 求解答案的过程中只需要加入归并排序的过程即可，因为要让左、右各自有序，来获得计算的便利性。
- 归并分治的代码套路：递归函数返回"当前范围的答案"，同时顺便把当前范围排有序；跨左右的统计放在 merge 之前做（此时左右两半已有序），统计完再正常 merge。
## 二、题目1：小和问题
- 题目描述：数组中每个数左边所有 <= 它的数的总和，称为这个数的小和贡献；所有数的贡献之和就是数组的"小和"。
- 举例：s = [1, 3, 5, 2, 4, 6]
```plain
s[0]左边 <= s[0]的总和为 0
s[1]左边 <= s[1]的总和为 1     (1)
s[2]左边 <= s[2]的总和为 4     (1+3)
s[3]左边 <= s[3]的总和为 1     (1)
s[4]左边 <= s[4]的总和为 6     (1+3+2)
s[5]左边 <= s[5]的总和为 15    (1+3+5+2+4)
小和 = 0 + 1 + 4 + 1 + 6 + 15 = 27
```
- 归并分治思路：大范围的小和 = 左半小和 + 右半小和 + 跨越左右的小和。算"跨越左右"时，对右半的每个数 arr[j]，要累加左半所有 <= arr[j] 的数之和；因为左右两半各自有序，可以用双指针不回退地一遍扫过：左指针 i 单调右移并维护累加值 sum，每个 j 直接 ans += sum，这就是"左右有序"带来的便利性。
- 测试链接：https://www.nowcoder.com/practice/edfe05a1d45c4ea89101d936cac32469
- 注意溢出：结果可能很大，用 int 会溢出，要返回 long 类型，笔试常见坑。
```java
// 返回arr[l...r]范围上小和的累加和，同时把arr[l..r]变有序
// 时间复杂度O(n * logn)
public static long smallSum(int l, int r) {
    if (l == r) {
        return 0;
    }
    int m = (l + r) / 2;
    return smallSum(l, m) + smallSum(m + 1, r) + merge(l, m, r);
}
// 返回跨左右产生的小和累加和；左右已有序，统计完让左右整体有序
public static long merge(int l, int m, int r) {
    // 统计部分：对右半每个arr[j]，累加左半所有<=arr[j]的数之和
    long ans = 0;
    for (int j = m + 1, i = l, sum = 0; j <= r; j++) {
        while (i <= m && arr[i] <= arr[j]) {
            sum += arr[i++];
        }
        ans += sum;
    }
    // 正常merge（同归并排序，略）
    ...
    return ans;
}
```
## 三、题目2：翻转对数量
- 题目描述：给定数组 nums，如果 i < j 且 nums[i] > 2 * nums[j]，就称 (i, j) 为一个翻转对，返回翻转对的数量。
- 测试链接：https://leetcode.cn/problems/reverse-pairs/
- 归并分治思路：大范围翻转对数 = 左半答案 + 右半答案 + 跨越左右的翻转对数。算"跨越左右"时，对左半的每个数 arr[i]，数出右半有多少个 arr[j] 满足 arr[i] > 2 * arr[j]；因为右半有序，右指针 j 单调不回退，累加 j - m - 1 即可。
- 注意溢出：arr[j] * 2 可能超出 int 范围，要转成 long 再比较：(long) arr[i] > (long) arr[j] * 2。
```java
// 统计l...r范围上翻转对的数量，同时l...r范围统计完后变有序
// 时间复杂度O(n * logn)
public static int counts(int[] arr, int l, int r) {
    if (l == r) {
        return 0;
    }
    int m = (l + r) / 2;
    return counts(arr, l, m) + counts(arr, m + 1, r) + merge(arr, l, m, r);
}
public static int merge(int[] arr, int l, int m, int r) {
    // 统计部分：对左半每个arr[i]，数右半有多少个arr[j]满足arr[i] > 2*arr[j]
    int ans = 0;
    for (int i = l, j = m + 1; i <= m; i++) {
        while (j <= r && (long) arr[i] > (long) arr[j] * 2) {
            j++;
        }
        ans += j - m - 1;
    }
    // 正常merge（同归并排序，略）
    ...
    return ans;
}
```
## 四、复杂度分析
- 两道题的解法和归并排序的时间复杂度一样，都是 O(n * logn)：递归式同为 T(n) = 2 * T(n/2) + O(n)，统计部分和 merge 部分都是双指针不回退的 O(n)。
- 额外空间复杂度 O(n)（辅助数组 help）。
- 暴力枚举所有数对是 O(n^2)，归并分治利用"左右有序"把跨左右的统计从 O(n^2) 降到 O(n)，这是它能快的原因。
## 五、补充与扩展
- 一些用归并分治解决的问题，往往也可以用线段树、树状数组等解法，时间复杂度也都是最优解，这些数据结构会在【必备】或者【扩展】课程阶段讲到。
- 本节题目都是归并分治的常规题，难度不大。归并分治还可以解决很多较难的问题，只要符合上面说的特征，比如二维空间里任何两点间的最短距离问题（《算法导论》原题），会在【挺难】课程阶段讲述。
- 还有一个常考的算法："整块分治"，会在【必备】课程阶段讲到。
- 聊：归并分治是精妙又美丽的思想传统。
## 六、总结
- 归并分治三问：大范围的答案能否拆成 左 + 右 + 跨左右？算跨左右时"左右有序"是否带来便利？都成立就套归并排序的框架。
- 代码套路：先递归左右，再在 merge 前用双指针统计跨左右的答案，最后正常 merge 让当前范围有序。
- 两个笔试常见坑：小和结果用 long 防溢出；翻转对中 arr[j] * 2 要强转 long 防溢出。
