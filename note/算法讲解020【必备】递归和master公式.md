## 一、从思想上理解递归：画调用图
- 对于新手来说，递归去画调用图是非常重要的，有利于分析递归的执行过程和结果。
- 以求数组 arr[l...r] 范围上的最大值为例（分治思想：左半最大值和右半最大值取较大者）：
```java
public static int maxValue(int[] arr) {
    return f(arr, 0, arr.length - 1);
}
// arr[l....r]范围上的最大值
public static int f(int[] arr, int l, int r) {
    if (l == r) {
        return arr[l];
    }
    int m = (l + r) / 2;
    int lmax = f(arr, l, m);
    int rmax = f(arr, m + 1, r);
    return Math.max(lmax, rmax);
}
```
- 对 arr = {3, 8, 7, 6, 4, 5, 1, 2} 画出调用图（每个节点是一次递归调用，叶子是 l == r 的 base case）：
```plain
                        f[0..7] = max(8, 5) = 8
                       /                    \
              f[0..3] = 8                    f[4..7] = 5
             /          \                   /          \
      f[0..1] = 8    f[2..3] = 7      f[4..5] = 5    f[6..7] = 2
       /    \         /    \           /    \          /    \
   f[0]=3 f[1]=8  f[2]=7 f[3]=6   f[4]=4 f[5]=5  f[6]=1 f[7]=2
```
- 递归执行的顺序：先一路向左下钻到 base case，拿到结果后逐层向上返回合并，最终得到 8。
- 任何递归问题都可以这样：先想"子问题是什么"，让子问题帮你干活（相信递归能返回正确结果），再想怎么合并，最后确定 base case。
## 二、从实际上理解递归：系统栈
- 递归不是玄学，底层是利用系统栈来实现的：每调用一层，系统把当前函数的参数、局部变量、返回地址压入系统栈；子调用返回后弹出，接着之前的位置继续执行。
- 递归的深度 = 系统栈的深度，所以递归太深会栈溢出（StackOverflowError）。
- 上面调用图中"向左下钻"的过程就是不断压栈，"向上返回合并"就是不断弹栈。
## 三、递归一定可以改成非递归
- 任何递归函数都一定可以改成非递归：不用系统帮你压栈（系统栈空间），自己压栈（堆上申请的内存空间）即可，讲解018 的二叉树非递归遍历就是最好的例子。
- 递归改成非递归的必要性：
  - 工程上几乎一定要改，除非确定数据量再大递归也一定不深。比如归并排序、快速排序、线段树、很多的平衡树等，后面都讲。
  - 算法笔试或者比赛中：能通过就不改（笔试数据量通常不足以爆栈，怎么快怎么来）。
## 四、master 公式：子问题规模相同的递归复杂度
- 使用前提：所有子问题规模相同的递归才能用 master 公式。形如：
  - T(n) = a * T(n/b) + O(n^c)，a、b、c 都是常数
  - 含义：规模为 n 的问题拆成 a 个规模为 n/b 的子问题，加上拆与合的代价 O(n^c)
- 三种情况（log(b,a) 表示以 b 为底 a 的对数）：
  - log(b,a) < c  -> 复杂度 O(n^c)
  - log(b,a) > c  -> 复杂度 O(n^log(b,a))
  - log(b,a) == c -> 复杂度 O(n^c * logn)
- 常见例子：
```plain
求最大值    T(n) = 2*T(n/2) + O(1)   a=2, b=2, c=0, log(2,2)=1 > 0 -> O(n)
归并排序    T(n) = 2*T(n/2) + O(n)   a=2, b=2, c=1, log(2,2)=1 = 1 -> O(n*logn)
二分查找    T(n) = T(n/2) + O(1)     a=1, b=2, c=0, log(2,1)=0 = 0 -> O(logn)
满二叉树遍历 T(n) = 2*T(n/2) + O(1)  同求最大值                        -> O(n)
```
- 注意：子问题规模不同（如 T(n) = T(n/3) + T(2n/3)）不能用 master 公式，要用递归树等方法估计。
## 五、一个补充结论
- T(n) = 2 * T(n/2) + O(n * logn)，时间复杂度是 O(n * (logn)的平方)。
- 证明过程比较复杂，记住即可。这个式子不满足 master 公式的标准形式（多乘了 logn），后面讲一些分治算法时会遇到。
## 六、总结
- 新手理解递归靠画调用图：想清子问题、相信子问题的结果、想好合并、定好 base case。
- 递归底层就是系统栈，任何递归都能自己压栈改成非递归；工程上怕爆栈要改，笔试能过就不改。
- master 公式用于"子问题规模相同"的递归：比较 log(b,a) 与 c，谁大取谁，相等补一个 logn。
