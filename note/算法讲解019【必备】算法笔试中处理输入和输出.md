## 一、两种测试风格
- 填函数风格：平台给你函数签名，只填写函数体（如 LeetCode、部分牛客题），不需要处理输入输出。
- ACM 风格：自己从标准输入读数据、向标准输出写答案（笔试、比赛最常见），输入输出处理是必须掌握的基本功。
- ACM 风格读取分两种场景：
  - 规定数据量：题目告诉你有几个数字、每个数字是什么，用 StreamTokenizer 一个一个读。
  - 按行读：没给数据规模（比如每行若干个数求和），只能 readLine 读整行再自己切分。
- 重要：不要用 Scanner、System.out，IO 效率慢，数据量大时会超时。Java 高效组合是 BufferedReader + StreamTokenizer / readLine + PrintWriter，其他语言有对等的写法。

## 三、ACM 风格：规定数据量（StreamTokenizer 写法）
- 三板斧：BufferedReader 把输入 load 进内存（高效、托管）-> StreamTokenizer 一个一个读数字 -> PrintWriter 作为输出的内存托管区，最后 flush 刷出去。
- 读数字固定套路：in.nextToken() 取下一个 token，用 (int) in.nval 拿到数值；循环条件 in.nextToken() != StreamTokenizer.TT_EOF 判断输入是否结束。
```java
public static void main(String[] args) throws IOException {
    // 把文件里的内容load进来，保存在内存里，很高效，很经济，托管的很好
    BufferedReader br = new BufferedReader(new InputStreamReader(System.in));
    // 一个一个读数字
    StreamTokenizer in = new StreamTokenizer(br);
    // 提交答案的时候用的，也是一个内存托管区
    PrintWriter out = new PrintWriter(new OutputStreamWriter(System.out));
    while (in.nextToken() != StreamTokenizer.TT_EOF) { // 文件没有结束就继续
        int n = (int) in.nval; // 二维数组的行
        in.nextToken();
        int m = (int) in.nval; // 二维数组的列
        int[][] mat = new int[n][m];
        for (int i = 0; i < n; i++) {
            for (int j = 0; j < m; j++) {
                in.nextToken();
                mat[i][j] = (int) in.nval;
            }
        }
        out.println(maxSumSubmatrix(mat, n, m));
    }
    out.flush(); // 千万别忘了，否则答案没刷出去
    br.close();
    out.close();
}
```

## 四、ACM 风格：按行读（readLine 写法）
- 场景：题目没给数据规模，比如"每行若干个数字，求每行的和"（牛客 7.A+B(7)），此时 StreamTokenizer 无能为力，只能按行读再自己切分。
- 套路：in.readLine() 读整行，split(" ") 切出每个数，逐个转 int 处理；返回 null 表示输入结束。
```java
public static void main(String[] args) throws IOException {
    BufferedReader in = new BufferedReader(new InputStreamReader(System.in));
    PrintWriter out = new PrintWriter(new OutputStreamWriter(System.out));
    String line;
    while ((line = in.readLine()) != null) {
        String[] parts = line.split(" ");
        int sum = 0;
        for (String num : parts) {
            sum += Integer.valueOf(num);
        }
        out.println(sum);
    }
    out.flush();
    in.close();
    out.close();
}
```
- 完整代码见 Code04_ReadByLine.java，测试链接：https://www.nowcoder.com/exam/test/70070648/detail?pid=27976983
## 五、空间申请：不推荐临时动态，推荐全局静态
- 不推荐：临时动态空间（Code02 的方式）。多组测试时每组都 new 新数组，频繁申请释放，常数时间开销大，大厂笔试或比赛中不推荐。
- 推荐：全局静态空间（Code03 的方式）。按题目给的最大数据量一次性开好静态数组，所有测试共用、不停复用，代码运行的边界用 n、m 两个全局变量规定下来。
- 关键细节：静态空间被复用时，上一轮用过的部分可能残留数据，需要手动清空要用到的部分（如 Arrays.fill(arr, 0, m, 0)），不能让之前的结果干扰这次运行。
```java
// 题目给定的行、列最大数据量
public static int MAXN = 201;
public static int MAXM = 201;
// 申请这么大的矩阵空间一定够用，静态的空间，不停复用
public static int[][] mat = new int[MAXN][MAXM];
// 需要的所有辅助空间也提前生成
public static int[] arr = new int[MAXM];
// 当前测试数据的行、列数量，把代码运行的边界规定下来
public static int n, m;
public static int maxSumSubmatrix() {
    int max = Integer.MIN_VALUE;
    for (int i = 0; i < n; i++) {
        // 之前的过程可能用过辅助数组，自己清空需要用到的部分
        Arrays.fill(arr, 0, m, 0);
        for (int j = i; j < n; j++) {
            for (int k = 0; k < m; k++) {
                arr[k] += mat[j][k];
            }
            max = Math.max(max, maxSumSubarray());
        }
    }
    return max;
}
```
- 完整代码见 Code03_StaticSpace.java。
## 六、StreamTokenizer 的坑与 Kattio（补充）
- StreamTokenizer 把数字按 double 解析，以下情况会读错：
  - 不溢出但很大的 long 类型数字（超过 2^53 精度丢失）。实测：输入 131237128371723187，读出来是 131237128371723184。
  - 科学计数法表达的 double 数字。实测：输入 5.6920E+0001（应为 56.92），读出来是 5.692。
  - 需要依次读取一个一个字符串处理的题目。
- 解决办法：使用 Kattio 类（Code05_Kattio.java 中给出完整实现），基于 StringTokenizer 按字符串读再 parse，就没有这些问题：
```java
Kattio io = new Kattio(); // 自动接入输入输出流
io.next();       // 读取下一个字符串（以空格或回车分割）
io.nextInt();    // 读取下一个int
io.nextLong();   // 读取下一个long
io.nextDouble(); // 读取下一个double
io.println("ans"); // 答案进入输出流
io.flush();      // 答案刷给后台
io.close();      // 关闭io
```
- 注意：不能因此放弃 StreamTokenizer 全用 Kattio，因为 StreamTokenizer 的效率还是比 Kattio 好。只有在 StreamTokenizer 无法正确读取时，才考虑 Kattio。参考链接：https://oi-wiki.org/lang/java-pro/
## 七、FastReader / FastWriter（补充）
- Code06_FastReaderWriter.java 提供了手写快读快写类（课上没讲）：FastReader 直接按字节缓冲读入再手工拼数字，FastWriter 用字节缓冲批量写出，速度比 StreamTokenizer 还快。
- 用法示例：
```java
FastReader reader = new FastReader(System.in);
FastWriter writer = new FastWriter(System.out);
int cha = reader.readByte();   // 读一个字符的ASCII码
int num1 = reader.readInt();   // 读一个int
long num2 = reader.readLong(); // 读一个long
writer.println(num1);
writer.close(); // close方法包含flush，会把结果刷出去
```
- 日常笔试用 StreamTokenizer 三板斧已经足够快，追求极致速度或数据量特别大时可以使用这套快读快写。
## 八、总结
- 填函数风格：只写函数体，辅助空间临时生成即可。
- ACM 风格：BufferedReader + PrintWriter 打底；规定数据量用 StreamTokenizer 逐个读数字；没给规模就 readLine 按行读再切分；切记最后 out.flush()。
- 空间申请：推荐全局静态空间按最大数据量一次开好、反复复用，注意清掉上一轮用过的部分。
- StreamTokenizer 读大 long、科学计数法 double、纯字符串场景会出错，换 Kattio；追求极限速度用 FastReader/FastWriter。
